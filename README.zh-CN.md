# Agent Runtime / WhiteBox · v9.0（Alpha 0.1.5）

> English: [README.md](README.md) · 日本語: [README.ja.md](README.ja.md) · 发布说明: [ALPHA-0.1.5-RELEASE.zh-CN.md](ALPHA-0.1.5-RELEASE.zh-CN.md)

**一个把「透明、节省、可审计」做成可比对读数、并且是单会话的 Agent 运行时。**

本文是当前实现的全面设计与交付报告，不是相对上一版的增量说明：它描述系统**今天是什么**、保证了什么，
以及每一条保证**怎么被量出来**。

---

## 摘要

多数 Agent 运行时只优化能力，三件事不被计量：模型到底看到了什么、花了多少、运行时为什么这样做。
WhiteBox 把这三件当作一等工程对象。

一个会话 = **一条只追加的事件流**。送给模型的每一个字节，都由**稳定前缀**（协议 → 规则 → 知识 L1 →
决策 L1 → 记忆索引）加上这条流拼成；前缀在相邻两轮之间**逐字节相同**，于是把重活交给提供方的前缀缓存。
知识与决策是**两棵同构的四层树**，正文按 id 取用，一个会话内同一正文最多拼一次。
每个动作都是**带标签的事件**；每个判断都是**带负例的闸门**；每次收尾都写一份**可复算的回执**。

参考负载上的交付读数：协议区 **25 行 / 5,234 token**；知识树 **10 / 25 / 46 / 445** 节点；决策树
**4 / 8 / 12 / 16**；内部全量测试 **1349 / 1349**；真实长会话的前缀缓存命中 **99.1 %**；423 轮任务台账
压缩 **45,888 → 16,599 字符（−64 %）**；收尾 **≈35 秒 / 5 轮**。

## 0. 一开始的要求，已经兑现

项目起点只有一句话：*单 session，尽可能透明、尽可能节省、尽可能可审计。* 本版把这句话收尾。

| 要求 | 机制 | 读数（2026-10-30） |
|---|---|---|
| **单 session** | 一个进程只拥有一条流；`/reset` 是结束它的唯一方式；`start` 从上一份末态开下一条 | `--stream` 只指向一个文件；续接与回放是**位置**语义，从不是合并 |
| **透明** | 只追加的事件；`Tag` 即身份；prompt 是算出来的对象，不是模板 | 12 个模块，逐模块字节贡献在台面上可见（`(Cached) / (Active) / (Runtime)`） |
| **节省** | 常驻只有 L1；L2–L4 按 id 取；一轮只组装一次；稳定前缀永不重写 | 前缀缓存 **99.1 %**（296,225 / 293,632）；协议 **5,234 token**（预算 5,600） |
| **可审计** | 标签、账本、带负例的闸门、收尾回执、决策报告 | **18** 项 block/report 检查；**242** 条坑集落点声明；回执指纹可重算 |

下面全是这张表背后的机制。

## 1. 为什么 Agent 运行时通常过不了这四关

1. **透明最先死。** prompt 现场拼装，没人能说清哪一段来自哪里，也没人能证明「预览」等于「实发」。
2. **成本变得不可见。** 历史越滚越长、每轮整段重发，账单按平方增长，缓存命中率从没被量过。
3. **审计变成考古。** 运行时自己的判断（取用、收尾、知识晋级）只留下日志行，没有结构化、耐久的痕迹。
4. **会话互相污染。** 用「全部带过来」实现连续性，于是每一节都比上一节更慢、更不可预测。

WhiteBox 对这四条各给一个机制，而不是一句纪律。

## 2. 设计不变量

| # | 不变量 | 由什么保证 |
|---|---|---|
| I1 | 除声明版本事件外，相邻两轮的稳定前缀逐字节相同 | 前缀指纹 + 版本书 |
| I2 | 历史只追加，绝不重写或折叠 | 代码里不存在折叠路径；到边界是换会话，不是压缩 |
| I3 | 一轮 = 一次组装；给人看的那份就是发出去的那份 | `Assert.Same(preview.Request, client.LastRequest)` |
| I4 | 同一节点正文每会话最多拼一次，之后只给指针 | 按 id 取 + 会话内去重 |
| I5 | 每个判断都有能把它判红的负例 | 闸门（18 项运行时检查 + 1,349 条单测） |
| I6 | 不静默跳过：坏输入带着位置 fail-closed | 解析层带行号的 `InvalidDataException` |

## 3. 架构

### 3.1 区与字节账

prompt 是一摞有名字的区域，每个区域有自己的字节预算与生命周期：

| 区 | 内容 | 生命周期 |
|---|---|---|
| **R1-P** | 协议区（v102）—— 内核常量，rank 0 | 稳定，直到声明版本事件 |
| **R1** | 规则 · 知识 L1 · 决策 L1 · 记忆索引 | 稳定前缀，只在变更时重新派生 |
| **R2** | 只追加的会话事件流（发生过什么的账） | 只增长，从不重写 |
| **R3** | 焦点 —— 当前任务此刻的着重点 | 逐轮 |
| **R4 / R5** | 白板 / 草稿 —— 跨会话的工作台面 | 收尾定格，绝不静默丢弃 |

台面上同时显示**上一次请求里每个模块的真实贡献**与**下一轮的预估**，并且明确标注：
预估永远不会被当成事实展示。

### 3.2 事件流就是唯一事实源

每条用户消息、模型输出、工具调用与结果、提示、决策、中断、收尾，都是一个带单调序号与标签
（`E001`、`E002`…）的事件。位置由流本身推导，流之外没有权威。由此得到三件事：

- 崩溃分析只读流尾（最后三条事件回答「它在做什么」）。
- 跨会话交接是位置语义：`S<k>/E###` 锚点，而不是被抄写一遍的散文。
- 任何读数都能从文件重新算出来，任何人、任何时候。

### 3.3 两棵同构的树

知识（我们知道什么）与决策（为什么这样选）形状相同：

```
L1 法则  →  L2 问题形状  →  L3 处理单元  →  L4 逐字证据
```

- 每个节点**恰好一个父**；深度恰好四层；每一层必须真的起**归组**作用
  （一个 L1 只盖住一个 L2 就是抽象失败，链闸门直接判红）。
- L1 常驻；L2–L4 按 id 取；一个节点正文每会话只进上下文一次。
- L4 是证据层：逐字、只追加，每条带 `src=` 锚点指回原文件。
- 节点 id 有规范形（`L<层>-<短名[a-z0-9]{2,16}>-<三位序号>`）；不合规的标记是**硬解析错误**，不是被跳过的行。

当前参考语料：知识 **10 / 25 / 46 / 445** 节点（516 条边）；决策 **4 / 8 / 12 / 16**。

### 3.4 十二个模块，一次组装

| 模块 | 职责 | 典型字节 |
|---|---|---|
| protocol | 内核契约（R1-P） | ~20.9 k 字符 |
| rules | 工程铁则 | ~31 k 字符 |
| knowledge | L1 法则 | ~5.6 k 字符 |
| decision | L1 取向 | ~1.5 k 字符 |
| memory-index | 分页索引，按需取 | 常驻 0 |
| append-stream | 会话历史 | 增长 |
| task-ledger | 一轮一行：意图 / 结果 / 终局 / 未决 | ~0.3 k 字符 |
| tool | 工具面（协议区） | 常驻 0 |
| note | 逐轮便签 | 不用时 0 |
| current-tail | 白板（R4） | 小 |
| dynamic-draft | 草稿（R5） | 小 |
| focus | 焦点（R3） | 小 |

台面按**本轮真实贡献的字节**给每个模块打标签：`(Cached)` 拼进了请求、`(Active)` 活版按需取、
`(Runtime)` 挂了但没贡献。标签来自**生成该请求的同一遍组装 trace**，不是第二次计算。

### 3.5 会话生命周期

```
收尾（收敛 + 水位 + 末态快照）
   → reset（归档旧流，会话关闭）
      → start（新空流，白板/草稿从快照承接）
```

- 收尾是一条固定流水线：`--check` → `--apply` → `--promote` → `--close` → `--check`；
  `--l4-sync` 把新证据搬进 L4，`--kn-plan/--kn-link` 把它们挂到正确的父上。
- 流水线是**机械的**：搬正文、抬版本、重建派生。语义判断属于模型，运行时不猜意思。
- 关闭的会话不挡下一个：启动时看到 `closed` 就开一条新流，并逐条打印它承接了什么。

## 4. 机制

### 4.1 节省

- **常驻是一个决定，不是意外。** 每棵树只有 L1 进前缀，其余可寻址。
- **一轮只组装一次。** 预览对象就是发出去的对象，用引用相等把它钉住。
- **稳定前缀。** 时间戳、计数器、环境值一律不许出现在增长段之前；增长永远排在最后。
  这一条就是缓存命中率能贴近理论上限的原因。
- **窗口是边界，不是挤压。** 到 1,000,000 token 的 80 % 就收尾换流，而不是悄悄降质。

### 4.2 透明

- **每个字节都有主。** 区栈、逐模块贡献、缓存命中率、上下文合计——全部读自同一遍组装 trace。
- **两个数不许混**：「本 task 写入」（累计）与「当前上下文」（上次实发的 prompt），分开显示、分开标注。
- **读数只从结构化源取**（事件类型、账本），绝不去刮人读文案。

### 4.3 可审计

- **闸门有牙。** 18 项运行时检查：前缀/版本、语料锁、账本对账、存档区一致、未纳版件、可达性前置、
  删除登记、知识树链（单亲 / 层序 / 可达 / 深度）、L4 来源锚、决策树链、决策库晋级、自上次发布以来的增长、
  坑集落点完整性。每条 block 级闸门都由**必须变红**的负例证明。
- **落点必须声明。** 每个新坑都要声明为 `gate / resident / human / todo`，指针不得悬空
  （今天 242 条声明；`todo` 有显式基线封顶，欠账不能悄悄累积）。
- **回执。** 收尾写一份带回执指纹的账；工作区变了而回执没变，本身就是一条红。

### 4.4 有停点的自主

- 决策库把**取向**（L1）一路编码到**逐字先例**（L4）。需要人决策时默认**停下来问**：给一到三个选项、
  各自后果，并给一条**引用其所依据 L1** 的建议。
- 连续工作由**显式停点**界定：主人给了停点，就用决策库把中间判断全部做掉、恰好在那个位置停；
  没给停点，先问停点。
- 这就是为什么「自主」不等于「不负责」：每一个自动判断都指得回一条库里的条目。

### 4.5 一个台面，三种语言

- v9.0 起只保留一个终端台面（TUI2），旧台面**整个退役**，不是藏在开关后面。
- 界面是**强类型文案表**：89 个键 × 英文 / 日本語 / 中文，**默认英文**，运行时可切。
  键名写错或漏项是编译错误；另有一条闸门断言「英文档屏面上不许出现汉字」。
- 诊断能力没有随旧台面消失：未捕获异常照样落盘（流末 + 指针 + 托管栈）。

## 6. 我们刻意不做的事

- **运行时不做语义猜测。** 模型输出的结构解析不出来，就报位置并停下，不编一个"看起来合理"的读法。
- **不静默降级。** 资源缺失就是 `source_missing`；取不到读数就说取不到，不打印 0 冒充。
- **不做无界上下文。** 不折叠、不摘要历史；会话边界是显式的。
- **不藏写操作。** 每一处耐久状态的变更都经过一个具名、可 grep 的入口，收尾回执覆盖它们。
- **不声称多用户 / 并行会话。** 一次一个会话是设计决定，不是疏漏；并行是另一条研究线。

## 7. 复现

```bash
cd kernel
dotnet build AgentRuntime.slnx -c Release          # 0 错误
dotnet test tests/AgentRuntime.Tests -c Release    # 公开切片 1347/1349
dotnet src/AgentRuntime.Cli/bin/Release/net10.0/AgentRuntime.Cli.dll --protocol-show
dotnet src/AgentRuntime.Cli/bin/Release/net10.0/AgentRuntime.Cli.dll --kn-check whitebox/workspace
```

`--protocol-show` 打印版本、规模与预算；`--kn-check` 打印各层节点数、边数，并对派生层做逐字节核对。
同样的输入，同样的读数。

## 8. 路线

1. **吞吐与延迟** —— 先量后优化；这也是它仍是 pre-release 的唯一原因。
2. **恢复语义覆盖** —— 旧台面退役带走的三条驱动式测试（决策报告绑定 / 自报显示 / 续跑上限），要在新台面上重建等价物。
3. **长程研究** —— 同一任务的多次会话，以台账作为可审计记录。
