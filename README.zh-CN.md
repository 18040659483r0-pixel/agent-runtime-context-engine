# Agent Runtime / Context Engine · Alpha 0.1.1

> 一个可部署、可度量、可完全自定义的 Agent 运行时。
> 这份文档描述 **Alpha 0.1.1 的稳定设计**；历史演进不在此文。

## 摘要

Agent Runtime 把「与大模型协作」拆成两件可工程化的事：

1. **上下文 = 稳定前缀 + 只追加事件流**。前缀逐字节稳定、可缓存；历史只追加、不改写。
2. **知识与决策 = 两棵同构的四层树**。只常驻 L1，L2~L4 按 id 取用；同一会话同一条正文只拼一次。

运行时只做**机械执行**（装配、校验、记账、取数、收尾），语义判断交给模型。所有读数可复算。

## 〇·核心特性（Alpha 0.1.1）

- **极致节省 token**：知识库**只常驻 L1**（787 B），L2~L4 按 id 取用；同一会话同一条正文只拼一次，第二次只给指针。冻结语料 **8.1 KB / 约 2,428 token**。
- **透明度**：事件流只追加、标签即身份；每次取用、剪枝、收尾、放行都留痕；读数从结构化源取，可逐字节复算。
- **可扩展性**：模块可插拔、收尾要件按声明扩展、知识树按边生长；规则/人格/用户/知识/决策/原则全是纯文本，改文本即改世界。
- **决策库 + 自动连续任务**：决策库与知识库同构，L1 常驻；旁路决策模块替用户作决定前必须同时满足决策库与原则书；到 80% 自动收尾 → reset → 继续同一任务，只有库中未讲清的 gap 才停下来问人。
- **知识库自动上行（0.1.1）**：收尾时由远端模型把 memory + 踩坑集 + handoff 收敛成 `L4 证据 → L3 处理单元 → L2 问题形状 → L1 法则` 的链；运行时负责 id 映射、去重、断链不写、结构校验、只追加。

## 1. 设计目标

- **可缓存**：稳定前缀不掺时间、随机、环境；改一个字节即视为版本事件。
- **可审计**：事件流只追加；标签是身份，位置只进账本。
- **可解释**：知识/决策是树，每条都有 id、层级与边；取用与剪枝可复盘。
- **可部署**：裸基线 + CLI，纯文本自定义，无代码改动。
- **可复现**：同输入 ⇒ 同字节；同命令 ⇒ 同读数。

## 2. 架构

### 2.1 上下文分层

| 区 | 内容 | 性质 |
|---|---|---|
| **R1-P** | 协议区（v74：15 行 / 10,701 字符 / 2,676 token） | 代码常量，Rank 0 |
| **R1** | 规则 · 知识 L1 · 决策 L1 · 记忆索引 | 稳定前缀，逐字节可复算 |
| **R2** | 事件流（`E###`，只追加） | 历史与工具结果 |
| **R3** | 焦点（本轮相关事件 id） | 动态 |
| **R4** | 白板（当前解法/步骤） | 动态 |
| **R5** | 草稿（未决项） | 动态 |

装配顺序：**R1-P → R1 → R2 → R4 → R5 → R3**。R3 居末，避免动态内容前置破坏缓存。

### 2.2 知识树（L1~L4）

```
L1 法则 → L2 问题形状 → L3 处理单元 → L4 证据
```

- 唯一标记：`<!--kn: <id> [next=<id,id>] [src=<path>]-->`
- id：`L<层>-<短名>-<三位>`，层号在 id 里。
- **只常驻 L1**；L2~L4 由模型用 `[KN] <id>` 按需取。
- **会话级去重**：同 id 首次取用拼正文；第二次只回 `kn-ref` 指针（含首次事件标签与序号）。
- 派生层由活版重算：`l1.xml` / `nodes.xml` / `summary.xml`，逐字节确定；结构校验（边、孤儿、seq）可复跑。

### 2.2.1 知识上行（收尾时生长，0.1.1）

踩坑与记忆不再停在 L4，而是由远端模型在收尾时**沿边收敛到 L1**：

- **材料**：当日 memory 正文 + 项目踩坑集正文 + handoff（有界摘录，不是只给文件名）。
- **一次模型调用**产出若干条链：`L4 证据 → L3 处理单元 → L2 问题形状 → L1 法则`；临时 id 由运行时映射为正式 id。
- **运行时只做机械校验**：重复链跳过、`src=` 空白或断链**不写**、边/孤儿/seq 结构校验、**只追加**、重建 `.derived`。
- **真机读数**：第 1 次 2 份材料 → 新增 8 节点（各层 2 条）；第 2 次 +4 节点（1 条链）；树 5→9；无新材料的干净态**不调模型**。
- 结果：下一次会话只需常驻 L1，细节按 id 取用 —— 上行线把「经验」变成可缓存的法则。

### 2.3 决策库

与知识树同构：`L1 取向 → L2 决策形状 → L3 决策单元 → L4 原话证据`。

- 决策库 **L1 进冻结 R1**，段序在知识 L1 之后。
- `USER-DECISION-ENTRIES.md` 收原始决策；收尾收敛进 `DECISION-LIBRARY.md`。
- `PROJECT-DESIGN-PRINCIPLES.md` 是项目活版，按需读，不常驻。
- 旁路决策模块（可热插拔）替用户作决定时，必须**同时满足决策库与原则书**；否则停下问人。

### 2.4 工具面

一次调用 = **一个 XML 元素**：

```text
[TOOL] <call><name>read</name><path>/abs/file</path></call>
```

- 成员按名取、顺序无关；多行正文逐字放入元素，不转义。
- 每个调用可带 `risk:` 声明；运行时不问人，只分类、留档、执行。
- 超出每轮节奏的调用**排队**，不拒绝、不丢失。
- 形状归一优先：`<TOOL>` / 裸 `<call>` / 原生标记残形会被归一到协议形状；围栏内的示例不算调用。

### 2.5 收尾

收尾是**可扩展模块**：每个要件一份声明，分 Core / Extension 两档。

- Core 红 = 记账并警告，默认**不阻断**；Extension 红只上账。
- 收敛点写入水位：存档版本、代码仓版本、坑集计数、活版↔存档区一致性、指纹。
- 绿收尾会清除上一条旧红注；带红收尾在收敛点行与账本双处留名。

## 3. 部署

部署版是一份**裸基线**：知识库 20 个种子节点（L1~L4 各 5 条），决策库 3 条种子。

```bash
./deploy.sh init ~/MyAgent
./deploy.sh provider --target ~/MyAgent --base-url https://api.deepseek.com \
  --model deepseek-v4-flash --api-key-env DEEPSEEK_API_KEY
./deploy.sh doctor  --target ~/MyAgent
./deploy.sh check   --target ~/MyAgent
./deploy.sh reset   --target ~/MyAgent --all
./deploy.sh run     --target ~/MyAgent [--cli]
```

- **路径**：包根由程序目录向上找 `config.xml`；包内布局固定；配置中的相对路径按配置目录解析；整个目录搬走仍成立。
- **provider**：只写 `BaseUrl` / `Model` / `ApiKeyEnv` / `ApiKeyFile` / `ContextWindow`；密钥只走 env 或密钥文件。
- **自定义**：规则 `AGENTS.md`、人格 `SOUL.md`/`IDENTITY.md`、用户 `USER.md`、知识 `knowledge.md`、决策库、项目原则——六份纯文本，改文本即改世界。

## 6. 边界（alpha）

- 知识上行按材料做**有界摘录**，超长材料会被截断（结果里明说）；它是「收敛」而不是「全量重写」。
- 网络工具（`web_fetch` / `web_search` / `http_request` / `web_download` / `web_search_extract`）是下一版能力，不在 0.1.1 范围内。
- 80% 自动闭环的 `ContextWindow` 默认 128,000，是假设值，可按模型改准。
- SWE-bench 只跑实跑子集，不是全量 300 条。
- 仅发布 macOS arm64 构建；其他平台需自行 `dotnet publish`。
