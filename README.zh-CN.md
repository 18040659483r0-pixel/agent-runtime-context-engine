# 前缀缓存最优的分层智能体架构（设计说明 II）

> 日期：2026-09-11　作者：本人（仅使用 OpenClaw 作为实现平台）
> 系列：第 II 篇。第 I 篇《[分层级混合形态模型架构](https://github.com/18040659483r0-pixel/hierarchical-hybrid-model-architecture)》解决 **Token 的数量**；本篇解决 **每一个 Token 的价格**。

---

## ① 核心主张

第 I 篇用分层把 **Token 数量**压下来；但只要上下文在每一轮被**重新拼装、重排序、重新摘要**，字节前缀就会改变，模型的 **前缀缓存（Prompt Cache / KV Cache）** 随即失效——已经算过的字节，被迫**按全价再算一遍**。这是单 session 模式下第二重、也更隐蔽的浪费：**不是 Token 太多，而是每个 Token 都在以全价重复购买。**

本架构的主张只有一句：

> **把上下文中一切可以不变的部分彻底冻结为字节级常量，并让变化只以「尾部只增」的方式发生。**

于是每一轮真正需要付费的新字节，只剩极小的增量 Δ，其余全部命中前缀缓存。用一句话概括：

> **让上下文在物理字节层面几乎不动——不动的部分，模型替你白算。**

## ③ 底层规则

| 层 | 名称 | 可变性 | 职责 | 对前缀缓存的作用 |
|---|---|---|---|---|
| **0 冻结区** | 铁则区域 + 全局知识索引 | 只读、版本化，仅收尾门禁可改 | 全局铁则 / 绝对底线 + 高度抽象的方法论目录 | **100% 字节恒定的前缀** → 每次必命中，且跨 Session 复用 |
| **1 增量区** | 双索引 + 追加日志 | 只增不写（append-only） | 专家索引 / 操作技能 / 记忆索引 / 执行工作区 | 尾部追加 → 命中率随长度趋近 100% |
| **2 实体/快照层** | Raw Logs · Snapshots · 知识源码 | 关联存储，不进 Prompt | 承接第 1 层的指针下钻 | **0 Prompt 成本**（只传指针） |
| **3 生命周期** | Flow 递增 / 恢复 / 收尾 / 自愈 | 事件驱动 | 唯一允许前缀发生变化的时刻（GC） | 在 Session 边界重置前缀 |

## ④ 关键机制（定义级结论）

### 4.1 极简增量律（必要性 + 极简）

上下文按「只增」演进：

```text
Context_N = Context_(N-1) ⊕ ΔFlow_N          （⊕ = 字节级尾部追加）
```

增量 `ΔFlow_N` 当且仅当同时满足以下三条，才称为**逻辑上必要且极简**：

- **必要性 Necessary**：去掉 `ΔFlow_N` 会改变可达行为（增量非空、非装饰）。
- **无冗余 Non-redundant**：`ΔFlow_N` 的任一字节都无法由 `Context_(N-1)` 推出。
- **只增不写 Append-only**：`Context_(N-1)` 仍是 `Context_N` 的字节前缀（永不重写前缀）。

形式化：

```text
ΔFlow_N = min{ |Δ| :  Behavior(Context_(N-1) ⊕ Δ) ≠ Behavior(Context_(N-1))
                      ∧  Δ ⊄ Closure(Context_(N-1)) }
```

**极简的直接后果**：一次更新的写入代价是 **O(|Δ|)**，而非 **O(|Context|)**。

### 4.2 缓存命中律

设第 N 轮上下文长度为 `L_N = L_(N-1) + |Δ_N|`，前缀缓存命中率为：

```text
H_N = L_(N-1) / L_N = L_(N-1) / ( L_(N-1) + |Δ_N| )   ⟶  1
```

只要坚持「只增不写」，`H_N` 随轮次单调上升并趋近 1；被重写的那一刻，`H` 归零。

### 4.3 主公式（缓存红利 / 成本律）

设 `P₀` 为未命中 Token 单价；`w` 为命中 Token 的价格比（`0 < w < 1`，命中即 `w·P₀`）；`C_in` 为「全不命中」时的输入成本；`C_out` 为输出成本（不受缓存影响）。

```text
C = [ 1 − (1 − w)·H ] · C_in + C_out
```

| 符号 | 含义 |
|---|---|
| `C` | 完成任务的总成本 |
| `C_in` | 无缓存时的输入成本 = `P₀ · L_in` |
| `C_out` | 输出成本（与缓存无关） |
| `w` | 命中单价折扣比（`0 < w < 1`） |
| `H` | 前缀缓存命中率 |

**有效单价**：

```text
P_eff = P₀ · [ 1 − (1 − w)·H ]
```

命中率每提高一点，有效单价就朝 `w·P₀` 逼近一点。

### 4.4 推论

1. **省率收敛**：当架构保证 `H → 1`，省率 `ρ = 1 − C/C₀ → 1 − w`。以业界常见的命中折扣 `w ≈ 0.1`（命中价约为全价的 1/10，各家不同）计，**长期省率趋近 90%**，且与任务长度无关。
2. **越用越省**：`H_N = L_(N-1)/L_N` 随 `N` 单调增；每一轮的边际输入价格 `→ w·P₀`。会话越长，缓存红利越大。
3. **极简即最省**：唯一未命中的部分是 `Δ_N`。把 `Δ` 压到必要最小值，同时最小化「写入量」与「付费量」；一旦重写前缀，`H = 0`，红利瞬间归零。**因此「必要性 / 极简」与「经济性」是同一条律令。**
4. **跨 Session 复用**：冻结基 `B`（第 0 层）在**所有 Session 中字节恒等** → 只按全价付一次，此后每次都按 `w·P₀` 命中。其成本被整个 Session 群体摊薄。
5. **与第 I 篇的合成律**：把两篇相乘，总成本 = 数量 × 单价：

```text
C = T(A) · P₀ · [ 1 − (1 − w)·H ]
  = T₀ · A^(−α) · P₀ · [ 1 − (1 − w)·H ]
```

   第 I 篇用「层」把 Token 数量 `T` 压小；第 II 篇用命中率 `H` 把有效单价压小。**两条曲线同向相乘，成本被二次压缩。**

### 4.5 附带收益：不可变性即完整性

冻结区只读、且**仅经版本化门禁改动**，带来两个副作用：① 任何不可信内容都无法篡改全局底线（**抗 Prompt 注入**）；② 铁则永远出现在字节流的同一位置，模型每轮看到的是同一份前缀（**抗指令漂移**）。**安全性与缓存友好性在这里指向同一个设计——不改，就是最优。**
