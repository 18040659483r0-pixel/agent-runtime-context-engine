### 18.2 思维链（reasoning_content）要不要回灌 —— 官方口径 + 同行做法

**DeepSeek 文档原文**（`guides/thinking_mode` · Tool Calls）：
> 「for requests carrying the **`tools` parameter**, the **`reasoning_content` must be fully passed back** to the API in all subsequent
> requests — even for turns where the model did not perform a tool call. If your code does not correctly pass back reasoning_content,
> the **API will return a 400 error**.」

并且分了两支：
> 「**带 `tools`**：previous turns 的 reasoning_content **should be passed back** 且**会拼进上下文**；
> **不带 `tools`**：**不必回灌**；**即便传了也会被忽略**（不会拼进上下文）。」

| 家 | 做法 | 依据 |
|---|---|---|
| **DeepSeek** | 带 `tools` 的请求：**必须回灌**（否则 400），并拼进上下文 | 官方 thinking_mode 文档 |
| **Anthropic**（extended thinking） | 用工具时 **必须原样回传 `thinking` 块**（有签名校验），否则报错 —— 同一族纪律 | 官方 extended-thinking 文档 |
| **OpenAI**（Responses API） | `reasoning` items 可经 `previous_response_id` 回传；推理模型推荐带着走 | 官方 reasoning 指南 |
| Cursor / Claude Code 等 | 走各家 SDK 的 **native tool calling** ⇒ 自动继承上面这套 | — |

⇒ **主流做法就是回灌**（用户直觉对）。**但它成立的前提是 native tool calling。**

**在 [WB] 现架构上不成立，三条硬理由：**
1. **[WB] 没带 `tools` 参数**（走的是**文本协议** `[TOOL] …`）⇒ API **直接忽略** reasoning_content ⇒ **白付 R2 的钱，零收益**。
2. **代价远不止「R2 大一点」**：CoT 是**每轮新增**的（M1 turn2 就 9.5k）⇒ 前缀**每轮都变** ⇒ **缓存命中崩**
   （现在 98~99% 命中；一崩 `prompt_cache_miss_tokens` 会从 ~500 涨到几万）⇒ 时间与价钱**双升**。
3. **我们抓到的 CoT 是「协议合规盘查」（噪声）**，不是有价值的推理 ⇒ 回灌 = 把噪声固化成先例，**更啰嗦，不会更聪明**。

⇒ 结论：**回灌能不能做，等价于「[WB] 要不要改成原生工具调用」** —— 那是另一个立项（记 T5）。

### 19.3 原生工具调用（native tool calling / function calling）—— 给用户的解释落点

它是**模型 API 层的一种能力**（不是模型"更聪明"）：
1. 请求里带 `tools: [{type:"function", function:{name, parameters(JSON Schema)}}]`；
2. 模型**不写文本标记**，而是返回结构化的 `tool_calls: [{id, function:{name, arguments(JSON)}}]`；
3. 客户端执行后把结果作为 `role:"tool"` 消息回传；
4. **形状由 API 保证** ⇒ `[TOOL] <call>` 写歪这类抖动**从根上没有**；
5. **CoT 回灌**只在这里有效（DeepSeek：带 `tools` 必须回灌，否则 400）。

⇒ [WB] 现在对的是 **OpenAI 兼容端点**，**能**改用 native tool calling；代价 = 协议区/归一层大改（很多兜底可退役）。

## 三十一、**甲 · 墙由账本速率导出（+ 一处硬缺陷）· 收尾机制查证**（2026-10-11 19:5x~20:1x · 用户定「维持 low + 选甲」）

### 31.1 ⚠️ 先记一处**硬缺陷**：声明的 600s 墙**从来没生效**

**结论：不是机制不同，是「谁来跑」不同。**
