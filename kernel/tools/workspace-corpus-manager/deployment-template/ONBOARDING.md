# ONBOARDING — 首次使用引导（Agent Runtime / WB · Windows x64 部署版）

> 这份语料是**部署版自带的首次使用引导**。首次进入 TUI2 时，远端 AI（官方 DeepSeek-flash）将依照
> 本文件引导新用户完成初始化、并借第一份「决策报告」教用户理解本系统。读完它，你应该能：
> 知道这是什么、它怎么想、以及第一步该做什么。

---

## 〇、先认识这台「会思考的机器」

你正在使用的，是一个 **Agent Runtime（上下文引擎）**——不是聊天框，而是**替你管理每一轮"该把什么放进上下文"的引擎**。

它的**巧思**在于三个思想，请记住，后面的每一步都在用它们：
1. **上下文有窗口，钱是模型的** —— 它只把「非放不可」的东西放进 prompt，其余留档、按需取用，所以 token 可控、不膨胀。
2. **一切进事件流、可续可查** —— 每一轮都是可追加的事件流（append-stream），关掉再开还能接上，白纸黑字可追溯。
3. **冻结前缀 + 活版分离** —— 铁则/知识/规则像「宪法」一样冻结在前；会话状态/草稿/记忆是「活版」，写满即收尾换流，互不污染。

## 一、第一次进入，发生了什么

你敲 `whitebox` 进入 TUI2 后，系统已经自动接通了远端 AI（官方 DeepSeek `deepseek-flash`）。
第一份「决策报告」不会直接让你干活，而是**引导你完成三件初始化**（按顺序，一样不落）：

1. **设定你的称谓** —— 以后 Agent 怎么称呼你、落进记忆与决策报告里。
2. **设定你的人格**（对 Agent 的期望协作姿态）—— 是审慎严谨、还是随机随性；你在 USER.md 里写的话，就是它长期记住的「你」。
3. **设定你的虚拟工作岗位** —— 你是架构师？写手？数据分析？这决定它默认怎么给你打下手（注入到 rules/岗位这一层）。

> 为什么要先做这三件？因为本系统的所有「个性化」都从这三处派生：称谓 → 落进 memory/决策；
> 人格 → 落进 USER.md（长期偏好）；岗位 → 落进 rules（按岗位过滤的专业铁则）。顺序错了会互相打架。

## 二、这套 workspace 的「地图」（每个文件/目录的用途与巧思）

| 位置 | 是什么 | 巧思 |
|---|---|---|
| `AGENTS.md` | 给 Agent 看的"工作手册"首页 | 一进来就知道边界与铁则，避免问傻问题 |
| `METHODOLOGY.md` | 方法论唯一家（顶层 L1/L2） | 把"怎么做事"压缩成抽象框架，不装海量细节 |
| `BULLETIN.md` | 公告板（索引化） | 各端/各会话 `svn update` 后先扫这里，不全量读 |
| `GLOSSARY.md` | 术语表 | 统一口径，防同一个词两个意思 |
| `rules/` `knowledge/` | 铁则 / 知识（冻结层） | 进 prompt 的是**最稳定的那部分**，其余留档 |
| `memory/` | 每日/长期记忆（活版） | 可追加、可收尾归档，是 Agent 的"日记本" |
| `handoff/` | 跨端交接 | 换机器/换 agent 不丢上下文 |
| `docs/PITFALLS.md` | 坑集 | 踩过的坑沉淀成 L3 细节，遇问题先查它 |
| `frozen-private/` | 私有冻结语料 | 随实例自带、结构闭合，不依赖共享 workspace |

**一句话记住**：**冻结的进 prompt（稳），活版的进档（变）**。理解这一点，就理解了 WB 大半个设计。

---

## 三、与它协作的三条铁律（也是它的三省）
1. **先说"要什么结果"，它再想"要怎么拆"** —— 决策报告就是它给"怎么拆"的交代。
2. **信息给足、别让它猜** —— 路径、版本、报错原文，越具体它越准。
3. **它是你的执行+参谋，不是你的嘴** —— 对外发言/发邮件/花钱等，它都会先停下来问你（安全网关）。

---

## 四、你的第一步（拿来就能用）

初次对话，你可以直接输入，例如：
> 你好，我是<称谓>，我的虚拟岗位是<岗位>。请按上面的引导，先告诉我：这套系统每个部分分别怎么帮到我，然后我们开始第一件事。

它会据此产出你的**第一份决策报告**，把"它打算如何陪你开展工作"讲给你听——现在，去体验吧。
