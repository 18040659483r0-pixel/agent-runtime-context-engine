## 1. dotnet 不在 PATH（2026-09-14，Mac）

- **现象**：`which dotnet` 找不到，但 SDK 已装在 `~/.dotnet`（10.0.400，2026-08-18 装的）。
- **处理**：① 软链 `ln -sf ~/.dotnet/dotnet ~/.local/bin/dotnet`；② 在 `~/.zshrc` 追加 `export PATH="$HOME/.local/bin:$PATH"`（带注释，可随时删）。
- **⚠️ 关键坑**：**光做软链不够**。`~/.local/bin` 只在 OpenClaw 网关进程的环境里存在，**新开终端的登录 shell 里没有** —— 用 `env -i HOME=$HOME /bin/zsh -lic 'command -v dotnet'` 才能验证真相（普通 `zsh -lic` 会继承父进程 PATH，给出假阳性）。
- **没做**：没装 brew cask（需 sudo、且会再装一份 SDK）；`/usr/local/bin` 属 root 不可写。
- **跨端注意**：本解决方案**刻意不写 `global.json`**，避免两端 SDK 补丁号不同导致 `dotnet build` 直接失败；Windows 侧用 `dotnet --list-sdks` 确认 10.x 即可。

## 1.5 xUnit v2 → v3 迁移（2026-09-14）

- **版本选择**：`xunit.v3` **3.2.2**（最新 v3 稳定）+ `xunit.runner.visualstudio` **3.1.5**（v3 线）+ `Microsoft.NET.Test.Sdk` **18.10.0**；**不上 v4.x**（作者定）。
- **csproj 必改**：加 `<OutputType>Exe</OutputType>` —— v3 的测试工程是**可执行程序**（自带 runner），不是库。
- **分析器新规则 xUnit1051**：所有接受 `CancellationToken` 的调用都要传 `TestContext.Current.CancellationToken`，否则 build 出警告；**故意传自定义 token 的用例**（如“已取消的 token 会向上传播”）用 `#pragma warning disable xUnit1051` 包住并注明原因——不要为了消警告把测试意图改掉。

## 2. `System.Text.Json` 默认会把中文转义成 `\uXXXX`（2026-09-14）

- **现象**：测试断言请求体含 `"content":"你好"` 失败 —— 实际发出的是 `"content":"\u4F60\u597D"`。
- **两层处理**：
  - **线格式**：写请求时用 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，中文原样发 UTF-8。理由：① 字节更少；② 上游分词更贴近自然中文（转义序列会把一个汉字拆成多个 token）→ 直接影响 Benchmark 的 Token 指标。
  - **测试**：不要用「原始 JSON 字符串包含中文」断言，改为 `JsonDocument` 解析后断言值；原始串断言只用于 ASCII（键名、字段存在性）。
- **反例（不要做）**：为了让字符串断言通过而关掉转义、却忘了这是**协议行为**——它是有意决策，必须有测试钉住（`中文原样发UTF8_不转义为unicode序列`）。

## 3. `HttpResponseMessage` 的 Content 读取与析构（2026-09-14）

- Provider 里读响应体必须用 `await content.ReadAsStringAsync(ct)`（带取消），并在 `using (httpResponse)` 内完成；
  否则取消时可能拿到半截 body 或被提前 Dispose。

## 4. 测试要「零网络」才能当尺子的地基（2026-09-14）

- Runtime 测试用 `FakeModelClient`；Provider 测试用 `StubHttpMessageHandler` 拦请求，断言 URL / 头 / body。

## 5. OpenAI 兼容端点的 baseUrl 语义（2026-09-14）

- DeepSeek 官方：`baseUrl = https://api.deepseek.com` **不带 `/v1` 也能通**（拼出 `/chat/completions`）；DeepInfra 则要带 `/v1/openai`。
- **不要自动补 `/v1`**：OpenClaw 侧已被这个坑咬过（带不带 `/v1` 语义不同、拼错就 404）。坚持「baseUrl 写什么就拼什么」，只做去尾斜杠。

## 6. 模块管线：用户消息只能由引擎追加（2026-09-14）

- **规矩**：模块的 `ContributeAsync` 只允许贡献「历史 / 规则 / 知识」类消息；**本轮用户消息由引擎统一 add 在最后**。
- **为什么**：如果让模块自己断言用户消息位置，一旦增减模块，消息顺序就会漂移 —— 消融实验立刻失效（对比的就不是「只差一个模块」了）。
- `SessionModule.ObserveAsync` 靠「最后一条即本轮用户输入」这个不变量取用户文本 —— 这个不变量由引擎保证，不要在模块里重复实现。

## 7. 消融测试怎么写才真的能守（2026-09-14）

- **不要**只断言「带 A+B 时消息数 = 3」。要断言：**去掉 A 后，剩余的贡献逐字相同**：
  ```csharp
  var expected = withBoth.Request.Messages.Where(m => m != rules).Select(m => (m.Role, m.Content)).ToArray();
  Assert.Equal(expected, withOne.Request.Messages.Select(m => (m.Role, m.Content)).ToArray());
  ```
- `ChatMessage` 是 **class 不是 record**，`m != rules` 是**引用比较** —— 这里正好是我们要的语义（“就是那一条实例”），不要改成值相等。

## 8. 上游前缀缓存按 64-token 块对齐（2026-09-14 实测）

- **实测**：同一 1810-token 前缀，第 1 次 `cache_hit=0`，第 2 次 `cache_hit=1664`（= **64 × 26**）→ 命中按 64 token 块计算；短前缀（几十 token）**永远 miss**。
- **别误判**：`cached = 0` ≠ 上游不支持缓存，很可能只是**前缀太短 / 前缀不稳定**。先用 T02 长前缀探针确认，再下结论。
- **对架构的含义**：想让缓存真省钱，必须把「稳定前缀」堆长且逐字节不动（→ V2 Frozen Context / V3 Append Stream）；动态内容一律往后放。
- 后续 55 次调用的阶梯实验再次印证：所有命中量都是 64 的整数倍（896/9856/256）。

## 9. 变体隔离：salt 必须放「冻结前缀最前面」（2026-09-14 自己踩的坑）

- **错误写法**：`$\"{tierText}\\n<<< end · {salt} >>>\"` —— salt 在尾部，前缀主体仍相同。
  后果：校准调用与前面的变体**已经把这个前缀烘热了** → 后面变体第 1 轮就直接命中（L2 实测 t1 命中 9856），**看起来像“运行时自动吃到缓存”，实际是实验污染**。
- **正确写法**：`$\"«{salt}»\\n{tierText}\"` —— salt 在最前，不同变体/档位**连一个字节的公共前缀都没有**。
- **自检手段**：每个变体**第 1 轮必须 cached = 0**（冷启动）。不为 0 就说明还有外部预热，本次数据作废。
- **为何容易忽略**：污染不会报错，只会让数字**变好看**。这类“沉默的乐观偏差”必须用纪律拦，不能靠眼看。

## 10. SVN 把中文 `.md` 判为二进制（`svn:mime-type=application/octet-stream`）（2026-09-14）

- **现象**：`svn add` 新目录下的中文 `.md` 时输出 `A  (bin)`，并被自动附上 `svn:mime-type=application/octet-stream` → SVN 不再当文本处理（**diff / 合并失效**；本工作区所有知识文件都靠 diff/合并）。
- **同源症状**：`svn diff` 报 `E000022 不能把字符串从 UTF-8 编码转换为本地编码`。**根因**：本机 `LANG` / `LC_ALL` 为空（C/POSIX locale）。
- **处理**：① `svn propset svn:mime-type "text/plain; charset=utf-8" <文件>` 覆盖；② SVN 命令统一带 `LC_ALL=en_US.UTF-8`。
- **不要做**：别给这些文件设 `svn:eol-style=native` —— 语料 / 冻结前缀要求**逐字节 LF 稳定**，Windows 检出转换会破坏字节、进而使前缀指纹变化、缓存整体失效。
- **适用范围**：跨端（001 端同样会遇到）→ 收尾时提升进 skill `svn-workflow`。

## 11. 基准里「变体共用 salt」→ 跨变体预热（2026-09-14，自伤）

- **现象**：T07 首版三个变体（`v1→v1` / `v1→追加尾部` / `v1→改头部`）**共用同一个 salt**（前缀最前那行相同）→ 变体 A 烘热的前缀被 B、C 直接命中：B、C 首轮 `cached=9472`（本应 0）。对照立刻失真，而且**症状看起来像「架构太好了」**。
- **铁律**：salt 必须**逐变体独立**——同一 run 内任何两个变体不得共享前缀字节。
- **守它（别靠肉眼）**：每变体首轮做**冷启动自检**，`cached != 0` 即打印告警并判该变体数据作废。
- **同类**：`--calibrate` 的校准调用也会烘热前缀 → 必须与变体前缀不同（salt 之后发生更保险）。
- 相关：`workspace/METHODOLOGY.md` §十·6；skill `llm-context-benchmark`。

## 12. `records.jsonl` 带 UTF-8 BOM（2026-09-14 发现，未修）

- **现象**：`benchmark/runs/*/records.jsonl` 首字节是 BOM → 严格解析器（`json.loads` 默认 utf-8）直接报 `Unexpected UTF-8 BOM`。
- **临时**：读的时候用 `encoding="utf-8-sig"`。
- **该修**：写 `records.jsonl` 时用 `new UTF8Encoding(false)`（无 BOM）—— 与「账本类文件 UTF-8 无 BOM」口径一致（见 `CloseoutWatermark.Save` 的做法）。
- 影响面：仅原始记录读取体验；结论可复算性不受影响（加 `-sig` 即可）。

## 13. `System.Text.Json` 枚举默认序列化成数字 → 账本不可读（2026-09-14，V3）

- **现象**：事件流 JSONL 写成 `{"kind":2,...}` —— 人眼读不出类型，diff 也看不出改了哪个枚举值。
- **正解**：读写 options 都加 `Converters = { new JsonStringEnumConverter() }` → `"kind":"Skill"`。
- **同类**：不设 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` 时中文被转义成 `\uXXXX`（文件不可读、diff 全花）。
- **守它**：测试断言落盘行里 `Contains("中文正文")` 且 `DoesNotContain("\\u")`。

## 14. `--modules` 覆盖时新建配置漏拷字段（2026-09-14，自己踩的）

- **现象**：`Program.BuildModules` 为「按名字覆盖模块」新建了一个 `RuntimeConfiguration` 并**逐字段手工拷贝**；V3 新增 `Stream` 段时没同步 → `--modules … --stream <path>` 时事件流路径被**静默丢弃**（模块起来了，流是空的，还不报错）。
- **铁则**：任何「按字段复制配置」的地方，**新增配置段必须同步**；能改成 `with` 式/深拷贝就别手抄字段。
- **同类风险**：`Frozen` 一旦加新子字段，同一处也必须补齐。
- **再次命中（2026-09-15，V4）**：新增 `snapshot` 段后，`Program.BuildModules` 那份手抄拷贝又差点漏掉 —— 已同步补上（`Snapshot = config.Snapshot`）。手抄字段的地方，新增配置段时**必须搜一遍**。

## 15. 「先重跑再校验」会掩盖版本闸门告警（2026-09-14，自己踩的）

- **现象**：跑迁移器时命令写成「先重跑 A/B，再 `--check`」→ 重跑覆盖了 `_manifest.json`，于是 `--check` 只报「产物与源一致」，**版本未 bump 的告警被抹掉**（后来靠 SVN diff 才发现内容真的变了）。
- **正确顺序**（写进 `tools/frozen-build/README.md`）：**先 `--check`**（此时应报「产物与源不一致」+「内容已变但版本未 bump」）→ **再**改 `versions.json` → **再**重跑 → **再** `--check`。
- **通用化**：凡是「产物 + 账本」两件套，**校验必须在重算之前**；否则账本被自己刷新，闸门永远绿。
- 同类教训：源**会被自动化改动**（本日 22:16 skill 巡检回写 → 语料内容变），所以 `--check` 要当**入场仪式**，不是一次性验收。

## 16. 恢复分叉后，快照账本里的 `streamPath` 会「过期」（2026-09-15，V4）

- **现象**：`--resume --fork <新流>` 之后，快照里记的仍是**原流**路径（分叉当轮会自动改写一份，但用户手上的配置文件 `stream.path` 不会自己变）。下一次 `--resume` 若不显式配/带 `--stream <新流>`，就会对着原流（含孤儿尾部）恢复 → 报 `ForkRequired` 或接错文件。CLI 目前只打印一行 ⚠️，**不代改配置**。
- **处理**：分叉后自己把 `stream.path`（或 `--stream`）指向新流；恢复报告里那行「快照记录的流路径与当前不同」就是提醒。
- **通用化**：账本里的「位置」一旦被外部动作改变（分叉 / 移动 / 归档），**要么当轮重写账本、要么调用方显式传参**，不要假设它会自己跟上。

## 17. 原子写失败的注入手法：把「目标路径」建成目录（2026-09-15，V4）

- **现象**：要证明「写入失败不留半成品」，但磁盘写满 / 权限不足在单测里不好稳定复现。
- **做法**：目标路径本身建成**目录** → `File.Move(tmp, target, overwrite: true)` 必然抛 `IOException`；然后断言：① 目录还在（目标一个字节没被碰）② 目录里没有 `*.tmp-*` 残留 ③ 旧快照仍能完整读回。
- **注意**：用 `Assert.ThrowsAny<IOException>`——不同平台 / 文件系统的具体异常类型不同，别写死某个子类。

## 18. `CloseoutWatermark.StreamCursor` 是 `int`，`SessionAppendStream.Cursor` 是 `long`（2026-09-15，V4）

- **现象**：V4 把 `--closeout` 的硬编码 `0` 换成真实流游标时，两侧类型对不上。
- **处理**：`Program.StreamCursorOf` 显式判界（`> int.MaxValue` 直接报错要求归档），**不静默截断**。
- **通用化**：跨层传账本数字，窄类型必须有闸门；截断等于伪造历史。

## 19. C# 重载二义性：`Append(kind,text,source)` 与 `Append(kind,text,tag)` 同签名（2026-09-15，V4.1）

- **现象**：给「只追加流」加第二个写入口（保留标签重放 / 分叉）时，想写成 `Append(kind, text, tag)` 的重载 —— 第三个参数同为 `string`，编译器报二义（`string?` 与 `string` 不构成重载区分）。
- **处理**：**起不同的名字**（`AppendPreservingTag`），并在注释里写清「谁是新身份、谁是保身份」。
- **通用化**：可选的 `string` 参数不要靠重载表达**语义不同**的入口；语义不同就换名字，重载只用于参数个数/类型真的不同。

## 20. 渲染里顺手 `Normalize` 会改顺序 —— 测试预期必须跟着「渲染规则」而不是「内部次序」（2026-09-15，V4.1）

- **现象**：选焦按**权重降序**选出 `[E004, E002]`，但 `Render` 里做了归一化（去重 + Tag 升序）⇒ 实际渲染 `[FOCUS] E002 E004`。第一版测试按权重序写预期 → 红。
- **处理**：把「**渲染顺序的唯一家 = 归一化**」写进注释（顺序敏感的东西必须有唯一声明处），测试预期按渲染规则写，并附一行算式说明权重为什么是这几个。
- **通用化**：**内部次序**（选焦序）与**输出次序**（逐字节）是两个概念；只要输出要逐字节稳定，就必须在输出处再归一化一次，且只此一处。

## 21. 组合根「顺手重排」会把闸门变成哑门（2026-09-15，V4.1，自伤）

- **现象**：为省事，`ModuleRegistry` 里把 `focus` 统一**追加到模块列表末尾**（这样焦点天然居末）。结果：配置里把 `focus` 写在 `append-stream` **前面**也静默通过 —— 第三道闸门（"排前面必须报错"）**永远不触发**，编出来的测试还得靠手工构造模块列表才碰得到。
- **处理**：改为**保序装配**（占位 → 原位替换），闸门立刻有牙（`--snapshot` 实跑验证：配置写反 → `exit=2` + 明确报错）。
- **通用化**：闸门要守的次序，**组合根不得替它兜底**；"我帮你排好"等于"我帮你不报错"。

## 22. 量 Runtime 开销必须 `-c Release`，且要看**放大数据量**后的增量（2026-09-15，V4.1）

- **现象**：Debug 下 `focus` 组比对照组每轮多 ~4ms，看着像「焦点很贵」。Release 暖进程一测：turn 2/3 两组都是 **0.2ms**；把流从 221 条放大到 2161 条，增量**仍是不变的 ~4ms** ⇒ 那是**首轮 JIT / 类型初始化的固定成本**，不是每轮成本。
- **处理**：多轮 `--chat` 一个进程量**每轮**开销；再放一个数量级的数据量，区分「固定成本」与「线性成本」。
- **通用化**：`dotnet run` 默认 Debug；任何「开销 / 性能」结论先声明构建配置，并用**数据量放大**做对照。

## 23. 权重阈值与衰减的**联合后果**要算出来，别凭直觉（2026-09-15，V4.1）

- **现象**：`minWeight = 1.0` 且 `decay = 0.5^(Δ/半衰期)`（半衰期 40 turn）时，某标签**只自报一次**只在 Δ=0 的那个 turn 入选（1.0 ≥ 1.0）；到 Δ=1 就是 0.9828 < 1.0 ⇒ 立刻退场。看上去像 bug，其实是**公式 + 默认值的联合后果**。
- **处理**：先按规格书实现、**不擅自调默认值**，把后果（"要留在焦点里，模型需每轮继续自报"）**报给主子**再定。主子 2026-09-15 决定下调：**默认 `minWeight` 1.0 → 0.95**（报一次管 3 个 turn：Δ=1 ⇒ 0.9828、Δ=2 ⇒ 0.9659 入选；Δ=3 ⇒ 0.9494 退场）。落地处 = `FocusOptions.DefaultMinWeight`（唯一声明处，配置段默认值随之继承），并用 `Focus_SingleReport_SurvivesThreeTurns` 把留存期钉死。
- **通用化**：阈值型参数与连续型函数组合时，先算「边界样本」再判断好不好用；改默认值属于**设计决策**（主子定），且必须**钉一个测试把行为区间写死**——否则下次改半衰期会静默改留存期。

## 24. 缓存文件与快照文件的**坏文件口径不同**，别抄错（2026-09-15，V4.1）

- **现象**：`focus.json` 是**加速缓存**（流才是真相源），`snapshot.json` 是**恢复点账本**。前者坏掉 ⇒ 当"没有缓存"（重算即可，正确性不受影响）；后者坏掉 ⇒ **必须报错**（宁可说不认识，也不装作认识）。
- **处理**：`FocusCache.Load` 捕获 `JsonException/IOException` 返回 `null`；`SnapshotStore.Load` 抛 `InvalidDataException`。两处注释互相点名，防后来者"统一口径"。
- **通用化**：**能否重建**决定坏文件的处置：可重建的（缓存 / 索引）降级，不可重建的（账本 / 事实）报错。

## 25. 规格自报的**规模数字**可能与逐字正文不符（2026-09-15，协议区 R1-P）

- **现象**：`REPORT-PROTOCOL-ZONE.md` §三 自报英文协议文本「7 行 / ≈560 字符 / ≈140 token」，但把该文本**逐字**落地后实测：**6 行 / 723 字符**；按规格自己在 §四/§七 Q8e 声明的口径「英文 ~4 字符/token」估 = **181 token** ⇒ **超出声明的 ≤160 token 预算**（旧版 `DESIGN-PROTOCOL-ZONE.md` §四 的「≤600 字符」同样不满足）。
- **处理**：纪律是「§三 逐字 + 不自行改设计」⇒ **正文一个字节都不删**（删正文 = 改协议 = 缓存归零，且是静默改设计）；把**执行上限**上修到能容纳逐字文本的最小档（`ProtocolText.MaxTokens = 200`），并把真实值（181）与声明值（160）**双双钉进测试**，同时在交付报告里列为偏离 #1。
- **通用化**：① 规格里的「规模 / 预算」是**可复算量**，实现时必须**实测并回填**，不能照抄估计值 —— 估计值与逐字正文不符时，**以正文为准、把预算缺口报出来**，不要偷偷改正文也不要偷偷放宽预算；② 两个量（正文 / 预算）的**唯一声明处**要放在一起（`ProtocolText` 同时持有 `Text` 与各上限常量），否则下次改正文没人会想起预算。

## 26. MSBuild：`<InternalsVisibleTo>` / `<AssemblyAttribute>` 是 **Item**，放 `PropertyGroup` 里必报 MSB4066（2026-09-15，V4.2）

- **现象**：为让「CLI 面」可测（I17），往 `AgentRuntime.Cli.csproj` 里加 `<InternalsVisibleTo Include="AgentRuntime.Tests" />`，直接放在 `<PropertyGroup>` 里 ⇒ `MSB4066: 无法识别元素 <InternalsVisibleTo> 中的特性"Include"`；换成 `<AssemblyAttribute Include="System.Runtime.CompilerServices.InternalsVisibleToAttribute">` 放在 PropertyGroup 里 ⇒ 同一个错。
- **原因**：这两个都是 **Item**（必须在 `<ItemGroup>` 里）；`PropertyGroup` 只认属性。错误话术（"特性 Include 无法识别"）**指向的是特性名，不是位置**，很容易往错方向找。
- **顺带**：XML 注释里**不能出现 `--`**（`MSB4025: An XML comment cannot contain '--'`）——`--tail-show` 这种命令行写法直接写进注释就炸。
- **处理**：`InternalsVisibleTo` 用 `AssemblyAttribute` 形式放进 `ItemGroup`；注释里把 `--tail-show` 写成 `tail 四条命令`。
- **通用化**：改 `.csproj` 时把 Item / Property 分清；**别在 XML 注释里写 CLI 选项原文**。CLI 面能用 `InternalsVisibleTo` 直接单测，比手感好得多 —— 代价只是一行 ItemGroup。

## 27. `dotnet run ... --nologo` 会把 `--nologo` **透传给应用**，未识别选项被当成「用户消息」（2026-09-15，V4.2，真机踩到）

- **现象**：`dotnet run --project src/AgentRuntime.Cli -v q --nologo -- --config X --tail "…"`：本意是「设一次白板就退出」，结果**真的向模型发起了对话**（`--nologo` 不是 `dotnet run` 的选项，落进了应用参数），而且模型回复末尾的自报被 `CurrentTailModule` 解析后**覆盖了白板** —— 白板里出现了模型自己写的「当前任务 / 待办 / 状态」三行。
- **原因**：`Program` 的 `default:` 分支把**任何未识别参数**当作本轮用户消息（裸词 = 消息，这是有意的便利设计）；`--xxx` 形式的未知选项**没有**被拦成 usage 错误 ⇒ 静默变成一次付费调用。
- **处理**：① 本机实验脚本改为**直接跑已构建的 dll**（`dotnet <path>/AgentRuntime.Cli.dll …`），彻底避开 `dotnet run` 的参数转发；② 白板操作与模型调用**分开跑**，看到 `[尾部] 已人工覆盖…` 才继续；③ 把这次意外当作管线证据入账（自报 → 解析 → 覆盖存储区，端到端真的通了）。
- **通用化**：① 命令行工具里「未识别的 `--xxx`」应当**报 usage 错**，不能等同裸词消息（否则每个手误都是一次真机调用）；② 跑真机的脚本**只跑 dll，不跑 `dotnet run`**，参数转发层越少越好。

## 28. 真机冷启动自检：**夹具逐字节相同 ⇒ 上一轮 run 已经预热**，第 1 轮 cached 不为 0（2026-09-15，V4.2）

- **现象**：同一套夹具（同 SEED、同 salt）连跑两次 V4.2 对照，第二次 A 组 turn 1 直接 `cached=2432`（第一次是 0/128）—— 数据看上去「缓存凭空出现」；「冷启动自检」（第 1 轮必须 cached = 0）直接把两轮数据都判成废数据。
- **原因**：上游前缀缓存是**跨进程、跨天**的服务端缓存；夹具字节没变 ⇒ 前缀就是同一段 ⇒ 第二次天然命中。#11 只说了「变体共用 salt」会在**同一次 run 内**互相预热，**没覆盖「跨 run」**这层。
- **处理**：给尺子加 `--seed`，salt 随种子变（`实验变体盐：{group}-{seed}`）⇒ 换种子 = 语料逐字节全变 = **真冷启动**；再跑一次，四组 turn 1 齐刷刷 `cached=128`（那 128 = 跨 run/跨组都逐字节相同的**协议区头 2 个 64 块** —— 它本来就该命中，是「协议区稳定」的正面证据）。
- **通用化**：① 冷启动自检的**前提**是「这段前缀从未上过网」——只保证「组间隔离」不够，必须让**夹具随 run 变化**（种子进 salt）；② 冷启动时若仍有一小块命中，先对一下那块的**字节来源**（是不是本来就不该变的协议区 / 系统提示），别一概当污染。
## 29. 量「模型遵从率」必须先设计**对的夹具**；测不出来时先怀疑量法（2026-09-15，V4.2，真机踩到 + 已纠正）

- **现象**：协议第 4 条写 `optional` 时，`[TAIL]` 自报率 **0/4**。改成**条件强制**后，**沿用同一夹具**又测出 **0/4**（换 `deepseek-v4-pro` 也 0/4）—— 一度被当成「模型不配合」。
- **根因（两层，都在夹具不在模型）**：① **探针题写「只回代号」**，与「末尾再加一段」**指令冲突**（实测规律：冲突时**用户那句话永远赢**）；② 更致命：老夹具里**任务/待办根本没变** ⇒ 按协议第 5 条「无变化可省略」，**省略本来就合规** ⇒ 该夹具**区分不了**「不遵守」与「正确省略」。
- **处理（已做，结论反转）**：另建量表 `benchmark/tools/v42-tail-compliance.py`（**任务每轮真的变化** + 探针问「现在在做什么/下一步」**不抢指令**）：
  - **B 组（纯协议驱动，用户消息不提 [TAIL]）自报率 4/4 = 100%**；X 组（显式要求）同为 100%；
  - 白板内容还**真的在累积**：当前任务 / 待办 / 遗留 / 暂停 / 已完成，逐轮跨任务传递；
  - 同一模型（flash）在旧夹具里是 0/4 ⇒ **差异 100% 来自夹具设计**。
- **通用化**：① 量「遵从率」必须让**条件真的触发**（否则测的是「会不会正确省略」）；② 探针**不得**与被测协议抢指令；③ **测不出来时先怀疑量法，再怀疑被测物**——否则会把「自己没给条件」写成「模型不行」（本次差点给协议打错刑）。

## 30. 协议允许一个回复带**多块**自报时，单块解析器会把别人的正文吞进来（2026-09-15，V4.3，设计时就撞上）

- **现象（推演 + 测试钉住）**：V4.3 的协议第 4 条允许模型在同一个回复里同时输出 `[TAIL]`（白板）与 `[DRAFT]`（草稿）。两个模块各自解析**同一份回复**：R4 的 `TryParseReport` 从下行找到最后一个 `[TAIL]` 头后**一路吃到结尾**，于是草稿块的 `[DRAFT]` 行与正文都被当成白板的行（白板被污染 / 或被判超限而整轮丢弃）；反过来先解析草稿也一样吞白板。
- **处理**：两个 `TryParseReport` 都加**分节符**——向下逐行时**遇到下一个块头即停**（块头清单 = `ProtocolText.ReportBlockHeaders` = `[FOCUS]` / `[TAIL]` / `[DRAFT]`，唯一声明处）；测试 `Draft_ParseStopsAtNextBlockHeader` 把「白板不吞草稿、草稿不吞自报行、两种次序都对」钉住。
- **为何以前的代码没暴露**：V4.2 的协议只定义了**一块**（`[TAIL]`），「吃到结尾」在那个世界里是对的；**协议一多块，解析就不再是「找头 + 吃尾」而是「找头 + 找尾」**。
- **通用化**：给文本协议加**第二种块**时，必须同时定义**分节符**；否则每个解析器都默默把下一块的正文当成自己的（不报错、只是内容错位 —— 最难发现的那类错）。

## 31. 用**一个数字**兼做「区的编号」与「区的先后次序」，重排一次就表达不出来（2026-09-15，V4.3）

- **现象**：V4.1/V4.2 里 `DynamicRank` 既是记号（R2=2 / R3=3 / R4=4 / R5=5）又直接拿来比大小（`rank < lastRank` ⇒ 违序）。V4.3 要把 **R3 排到最后**（R2 → R4 → R5 → R3）—— 但 R3 的编号永远是 3，无论怎么排序都比 R4(4)/R5(5) 小 ⇒ **闸门根本无法表达新规范序**，只能靠叫「位置」的另一个函数。
- **处理**：**拆开两个概念**：`DynamicRank`（区编号，只用于话术/身份）+ `DynamicPosition`（规范序下标，只用于比较）；规范序本身只在一个数组里声明一次（`DynamicSequence = [RankStream, RankTail, RankDraft, RankFocus]`），话术引 `DynamicSequenceText`。
- **通用化**：**身份**（是几号区）与**策略**（排第几）是两件事，第一次重排策略时就会打架；两者从一开始就分开声明，重排就只是改一个数组。


## 32. md 知识库里混进源正文标题 ⇒ 一次解析出 96 个「技能」（2026-09-16，skill-repo）

- **现象**：源技能正文本来就有 `## 适用` / `### M1. …` 这类标题；第一版解析器把「任意 `## X`」当技能头 ⇒ 一次解析出 **96 个"技能"**。
- **处理**：只有「**下一行是 `<!-- skill: … -->` 标记**」的 `## X` 才算技能头（标记是唯一判据）。
- **通用化**：用**扁平文本**承载**层级结构**时，标题级别不是身份；要一个**显式标记**当身份（否则用户正文里的同级标题会冒充结构）。

## 33. L3 条正文的**前后换行**与**分隔空行**歧义 ⇒ 往返只能到 21/27（2026-09-16）

- **现象**：条正文常自带前导/尾随空行；靠启发式（"分隔空行不算内容"）往返只到 21/27，写死规则反而 0/27。
- **处理**：在条首加一行 **`<!--wrap: lead trail-->` 显式记录前后换行数** ⇒ 27/27 逐字节。
- **通用化**：**往返（round-trip）不允许靠猜**；把「不可见的差异」**显式记进载体**，让重放是确定性算术而不是启发式。

## 34. 缓存按「源 sha」只保留**最后一次**响应 ⇒ 换提示词后回切要重花钱（2026-09-16）

- **现象**：以为"回切旧口径走缓存、0 调用"，实际缓存只留最新一条 ⇒ 回切也要重抽（1 次调用）。
- **通用化**：**别把"缓存"当成"历史"**——缓存是加速器（可被覆盖），历史要显式另存（如原始响应归档）；引用缓存做的**成本承诺**必须写成"预期"而不是"保证"。

## 35. 子会话跑长任务时，**中途发的规格变更只会排队**（2026-09-16，编排）

- **现象**：一次性发了 3 条规格修正（阈值 10%→15%、双条件、版本命名），子会话整轮跑完才可能看到 ⇒ 产出按**旧规格**成形（今天两次）。
- **处理**：要么**等交卷再发**下一条规格，要么**接受重跑**；并**在产物里记录"裁定时的规格值"**（阈值/上限等），事后一眼看出哪批是按旧口径做的。

## 36. 崩溃留下的**孤儿版本文件**：用「指纹重算」抓，不用眼看（2026-09-16）

- **现象**：进程崩在写版本与记账之间 ⇒ `versions/` 里多出一个**账本不认识**的快照。
- **处理**：`--check` 的「**版本完整性（逐版本指纹重算）**」把它抓出来；本次是崩溃产物（非用户数据），人工清理。
- **通用化**：多文件状态（md + 版本 + 账本）必须有**交叉校验**，否则"少记一笔"永远静默。

## 37. 交接文件名前导编号重复（两个「04」）⇒ `H-<nn>-###` 会撞 id（2026-09-16，知识库统一）

- **现象**：`workspace/handoff/` 里同时存在 `04-NodeMesh与IconForge-同步通知-给001.md` 与 `04-授权系统设计.md` —— 前导编号都是 `04`。按「交接 id = `H-<nn>-###`（nn = 文件名前导数字）」派生时，两个文件的第 1 条都想要 `H-04-001` ⇒ id 不唯一。
- **处理**：id 的 `nn` **不允许**只取裸前导数字当唯一键。派生器按**文件名排序**处理，同号冲突时给**后续文件**加小写字母后缀（第一个保持裸号 `04`，第二个 `04a`），保证唯一 + 确定 + 不静默。工具 `l3-unify.py` 已实现并落账本。
- **通用化**：**文件名前导编号不是唯一键**，不能直接当 id 片段；任何「从文件名提取的短码」进 id 前必须先做**冲突自检**（重复 ⇒ 确定性消歧或显式报错），否则两个文件的内容会互相覆盖对方的地址。

## 38. 坑集节号有非整数（`1.5`），且「N 条」计数与 `## ` 标题数不符 ⇒ 用节号当 id 会撞/漏（2026-09-16，知识库统一）

- **现象**：`PITFALLS.md` 有 `## 1.` / `## 1.5` / `## 2.` … `## 36.`。口头说「36 条」，实际 `## ` 标题是 **37 个**（`1.5` 是第 2 个）。若拿节号当 id：`1.5` 无法映射成 3 位整数，且 `## 2.` 之后所有号都偏移 1。
- **处理**：id 的 `<NNN>` 取**文档序**（1-based 序号，第 1 条 = `001`，与 skill `S-<short>-<seq>` 同构）；「人类编号」（1. / 1.5 / 2. …）**只进 `title`**，不进 id。这样 id 唯一、稳定、与节号解耦；计数以**派生器实际解析到的条数**为准，不以口头宣称的「N 条」为准。
- **通用化**：**人类给条目标号 ≠ 机器地址**。手写编号会插入非整数（1.5）、会漏重号，不能当稳定 id；id 一律用文档序，人类标签放 `title`；「一共多少条」以**派生结果**为准（可复算），不信嘴说。

## 39. 演示/转录里混入**墙钟时间**（开销 ms）⇒ 重跑 `demo.sh` 不是逐字节相同（2026-09-16，TUI 演示）

- **现象**：`demo.sh` 重跑后，`frame-96x30.txt` / `transcript.txt` 里的「开销 X.Xms」「总ms」会漂（如 6.6ms → 6.4ms）；但「字节 / 指纹 / 版本 / 合计」这些列是**确定性**的（协议文本不变 ⇒ 逐字节不变）。
- **处理**：帧/转录里凡是**墙钟 / 随机 / 环境值**（`开销ms`、`总ms`）重跑都会漂；对「逐字节一致」只锁**确定性部分**（字节 / 指纹 / 版本 / 合计），不比墙钟数字（或先把墙钟数字归一化再 diff）。
- **通用化**：**「逐字节一致」只对确定性产物成立**；产物里一旦混入墙钟/随机/环境值，重跑就不是逐字节相同。要在产物里把「确定性部分」与「墙钟部分」分开标注，diff 时只锁确定性部分。

## 40. 验证闸门时的「量法假阴性」三连（2026-09-16，验收）

- **通用化**：**「没复现」≠「没有」** —— 测不出来先怀疑自己的量法（同 METHODOLOGY §十·22）。负例要能说清「改了哪个字节 / 谁读它 / 预期哪条闸门变红」。

## 41. 窄豁免必须 fail-closed（2026-09-16，发布扫描）

- **现象**：给 `knowledge.md` 的技能标记行做 `src:` 豁免，若用宽松匹配（只匹配 `src: ‹redacted›`）会把**正文里**的真本机路径一起放行。
- **处理**：豁免正则**整行严格匹配**（字段序 / 字段名 / enum 值全要对），任一不符即**不豁免**；必须跑两个例子钉住：① 打乱字段序 ⇒ 重新命中；② 干净目录 ⇒ `exit 0`。
- **通用化**：**豁免的默认方向是「不豁免」**；豁免范围要能用一句话说清，且被负例钉死。

## 42. 知识库正文的硬红线：元数据豁免 ≠ 可发布（2026-09-16，发布扫描）

- **现象**：以为「豁免 `src:` 标记行」就能发布 `knowledge.md`；实测正文仍有 **10 处**硬红线：内网 SVN 地址 + 账号名、`‹redacted›` 路径、4 处真本机路径、2 处 `<home>` 占位示例、**2 处网盘地址**。
- **处理**：**元数据行与正文行分开判**；发布前**真跑** `tools/pre-publish-scan.sh` 并把命中**按类别**列清。收口二选一：正文改主机中性写法（`<workspace>` / `svn://<host>/…` / `<网盘地址>`，需记账写入 + 晋级新版本）或该文件**不进发布集**。
- **通用化**：**「不含凭据」不等于「可对外」**；只有跑过扫描、且命中逐条解释过，才配说「可发布」。

## 43. 文本协议的块头必须**在行首**：行中间的 `[TOOL]` 既不算批准、也不算调用（2026-09-16，工具面）

- **现象**：写测试时造了 `"好的，我已批准：[TOOL] write {…}"`，期望「模型自批不算 ⇒ 拒绝」。实际**连解析都没发生**（无 `TOOL_DENIED` 事件、无审批记录）—— 因为 `[TOOL]` 在行中间，`ToolReport` 的块头判据是「trim 后以块头开头」（与 `[FOCUS]` / `[TAIL]` / `[DRAFT]` / `[L3]` 同一条分节纪律）。
- **处理**：块头一律要求**行首**（家族一致）；测试把两条路都钉住：① 模型自称批准 + 行首 `[TOOL]` ⇒ **拒绝**；② 行中间的 `[TOOL]` ⇒ **不识别**（只有 user/agent 两条事件，文件确实没被写）。
- **通用化**：解析器的「严格」有**两个**失败面 —— 「拒了」是响的、「不认识」是**静的**。只测前者会漏掉后者；凡「不识别 ⇒ 什么都不发生」的路径，必须有一条断言**数事件条数**（证明确实什么都没发生，而不是「发生了但没记」）。

## 44. 零注入模块在确定性闸门里按 R2 类计次序 ⇒ 配置里放错位置会被判「动态区违序」（2026-09-16，工具面）

- **现象**：`tool` 模块 `ContributeAsync` 一个字节都不加（零注入），但 `DeterminismGate.DynamicPosition` 按「不是 R3/R4/R5 ⇒ R2」归类 ⇒ 配置写成 `["append-stream","focus","tool"]` 会被判「R2 出现在 R3 之后」而**报错**（闸门故意只报错、不纠正）。
- **处理**：`tool` 写在 `append-stream` 之后、`current-tail`/`dynamic-draft`/`focus` **之前**；这条纪律写进 `KnownModules` 的注释与 `DESIGN-TOOL-FACE.md` §七（配置的人能看见）。
- **通用化**：新增模块时除了「注入什么」，还要问一句「**它在动态规范序里属于哪一类**」；「零注入」不等于「不占位置」—— 位置是按**类**算的，不是按字节算的。

## 45. 新增配置段当天就要补进 `RuntimeHost.BuildModules` 的 `effective`（PITFALLS #14 的重演）（2026-09-16，工具面）

- **现象**：V6 加的 `skill`（L3 地址表路径）没被抄进 `RuntimeHost.BuildModules` 里手抄的那份 `effective` 配置 ⇒ 一旦用 `--modules` / `--bare` 覆盖模块列表，`skill.repo` 被**静默丢掉**（「按 id 装载」无声失效）。
- **处理**：补上一行 `Skill = config.Skill` + 注释；`BuildModules` 现在也把工具面的沙箱/闸门/账本透传给 `ModuleRegistry.Create`。
- **通用化**：`BuildModules` 是**手抄字段**的结构性风险点（#14 已记过一次）。判据很简单：`RuntimeConfiguration` 每加一个配置段，就在同一提交里回答「`BuildModules` 抄了吗」——漏了不报错、只是**静默丢配置**，这类 bug 只能靠纪律 + 代码里的同一处注释兜。

## 46. 审批面被右栏**截断**⇒「知情」变成假的（2026-09-16，TUI 审批）

- **现象**：`SplitRenderer` 对详细块一律 `TruncateTo(RightWidth)`。审批面一放进去就被截成 `[审批] 动作：write /private/tmp…` —— **真身路径看不全**，而审批的设计前提正是「人看见的就是真身」（S1/S2）。
- **处理**：`SplitFrame` 加 `DetailWrap` 开关，**只在待审批时打开**：详细块按 `RightWidth` **折行**（`TerminalText.Wrap`）而不是截断；行数变多没关系，那块本来就能滚。
- **通用化**：**「显示有预算」与「审批必须完整」是两条冲突的规则**，要显式分优先级 —— 凡是「人要据此做决定」的内容（审批面 / 报错原文 / 完整路径），**折行永胜截断**；纯粹信息型的（状态表、目录）才允许省略。

## 47. 端到端夹具三连坑（按键 / 提示吃 stdin / 回显缺块头）（2026-09-16，CLI+TUI 审批 E2E）

三个都让「测试红了但产品是对的」，属于**量法错**（§十·31 同一族）：

1. **整段写入 PTY ⇒ TUI 收不到键**：一次性 `write(整行 + \r)`，TUI 的重绘节奏下按键丢失；**逐字符 + 小间隔**写入才稳（`for ch in msg: write(ch); sleep(0.01)`，最后单独发 `\r`）。
2. **CLI 先问收尾提示**：有未收尾内容时 CLI 会在跑轮次**之前**问「现在就收尾吗？[y/N]」，它先吃掉 stdin 的 `y` ⇒ 审批面永远等不到答复。E2E 驱动必须按**提示顺序**应答（先 `n` 给收尾，再给审批）。
3. **mock 回显的两个坑**：① 回显内容**没有行首块头** ⇒ 解析器不认（`#43`），要在夹具里补成 `[TOOL] …`；② 夹具取的是**第一条** user 消息，多轮时会拿**旧目标** ⇒ 改成「取最后一条以 `@tool ` 开头的 user 消息」，并且每轮跑前清流。
- **通用化**：E2E 夹具**本身**要当被测物一样审：**谁先读 stdin / 输入怎么切分 / 状态怎么跨轮残留**，三处各能制造一次假红。

## 48. 量法错三连：取证据的通道被"吞"掉（2026-09-16，SVN 操作）

- **现象**：一小时内三次把"正确"判成"错误"：
  1. `cmd | tail -N` 之后量 `$?` ⇒ 量到的是 **tail** 的退出码（`build-frozen-corpus.py --check` 明明 exit 1，我读到 0）；
  2. **`svn log -l 1` 在「工作副本路径」上报的是 BASE，不是 HEAD** ⇒ 刚提交的 r581 看不见，以为"没提交成功"；
  3. `svn cat <工作副本路径>` 在**树冲突路径**上会失败，被 `2>/dev/null` 吞掉 ⇒ 我拿到的"仓库版"其实是**空文件**，于是判"DIFFER"（其实两边逐字节相同）。
- **处理**：① 闸门判定**直接跑、不接管道**；② 判提交成败用 `svn update` 后的版本号或 `svn log -r HEAD`；③ 取仓库版走 **URL**（`svn cat <URL>/…`），并且**不要**给可能失败的通道加 `2>/dev/null`。
- **通用化**：**关掉静默、指定权威来源** ——「静默失败 + 我以为它表示别的意思」是假结论的标准配方（`METHODOLOGY` §十·35）。

## 49. `commit` 后紧跟 `update` 的 add/add **树冲突**（内容其实相同）（2026-09-16，SVN 操作）

- **现象**：`svn commit` 成功（r582 就是本次提交）后立刻 `svn update`，两个**新加文件**报 `local file add, incoming file add upon update` 树冲突，`svn status` 显示 `C`；随后文件被标 `R`（替换），像是要再提交一次。
- **判定**：先证实**内容是否相同** —— 用 URL 取 r582 的版本与本地 `cmp`（本次 **IDENTICAL**）⇒ 属**假冲突**，不丢任何东西。
- **处置**：`svn resolve --accept=working <paths>`（**该类冲突不适用 `--accept=theirs-full`**，会报 `W195024`）→ 再 `svn revert <paths>` 回基线（内容相同 ⇒ 不产生空提交）。
- **预防**：**`commit` 之后先 `svn status`，再 `svn update`**；出现 add/add 且内容一致 ⇒ 按上面两步收口，**不要**顺手再提交一次。


## 50. `svn commit -F <文件>` **不给路径** ⇒ 提交工作副本里**所有**改动（2026-09-16，SVN 操作）

- **现象**：用 `svn commit -F /tmp/msg.txt` 提交"must-ask 档"这一件事，结果把**同一次工作里的另一件事**（Stage 0 文档 + `shadow-compose.py` 修复）一起提交进了同一个 revision（r588）⇒ 提交信息与实际内容不符。
- **根因**：`-F` 只提供**提交信息**；**提交哪些路径**是另一件事 —— 不给路径就是"工作副本里所有已改动/已 `add` 的"。
- **处置**：`svn propset svn:log --revprop -r 588 …` 试改提交信息 ⇒ **被拒**（`E175008`：仓库未开 `pre-revprop-change` 钩子）⇒ **改不回来**，只能在后续提交/公告板里说明。
- **预防**（两条一起用）：① **提交信息一律 `-F <文件>`**；② **要提交哪些路径必须显式列出**（尤其当天有第二件事时）。**忘了就等于没有"按事提交"这回事。**

## 51. 多行任务喂进 CLI/TUI 的 REPL ⇒ 一个任务被拆成 **N 轮**（2026-09-16，Stage 0 夹具）

- **现象**：把一份 7 行的任务描述整段喂进 `--ui plain` 的 REPL，事件流出现 **14 条**（7 问 7 答）、`/hits` 记 7 轮 —— 看起来像"模型跑了 7 轮"，其实是**夹具**把每一行当了一次用户输入。
- **根因**：REPL 是**面向行**的（一行 = 一次输入），对多行文本没有"整段提交"语义。
- **预防**：夹具喂任务前**压成单行**（结构用 `①②③` 或 `；` 串起来）；判"跑了几轮"**只信事件流**，不信终端看起来像几轮。

## 52. 夹具的"安静判据"太短 ⇒ 把长回复截成 **0 事件**（假失败）（2026-09-16，Stage 1 夹具）

- **现象**：第一版驱动设"25 秒没有新输出就算跑完"，结果一次真机运行报 **0 事件 / 0 轮** —— 看着像"什么都没发生"，实际是**模型还在生成**（那一轮 provider 耗时 **91.3 s**、completion 18k token）就被夹具打断。
- **根因**：把"安静"当成了"结束"；而**长回复的安静期可以远大于普通一轮**。
- **预防**：安静阈值按**最长一轮**留量（本次 25 s → 100 s）；并且**报告里要区分"真的没产物"与"被我打断"**（本次若只看 0 事件就会写出完全错的结论）。

## 53. 结构变化后，**脚本/夹具/配置里还指着旧路径**（"三处同步"的第三例）（2026-09-16）

- **现象**（同日两例）：① `tools/shadow-compose.py` 的语料清单还写着改名前的 `OWNER.md` / `METHODOLOGY.md` / `memory/INDEX.md` ⇒ 对照表里出现 3 行「（不存在）」；② `tools/skill-repo/selftest-gates.sh` 仍 `cp -R ~/.openclaw/workspace/skills/<skill>`，而本机 `skills/` 已在「工作区侧收敛」时**卸载** ⇒ 负测直接跑不起来。
- **根因**：#36 说的"三处同步"只覆盖了 spec / 账本 / 文档 —— **引用点还包括脚本的输入清单、负测夹具的输入路径、配置里的地址表**。
- **预防**：改名/下线任何目录后，**grep 全仓引用点**再收工；把"引用点清单"当成"三处同步"的第四处。

## 54. 实现有了、**配置没启用** ⇒ 功能空转（2026-09-16，知识库接线）

- **现象**：`[L3]` 自报 → 按 id 装载 L3 的**实现早已在**（V6），但三个配置都没有 `skill.repo` ⇒ 接线**整体空转**；待办里被记成"尚未实现"。
- **根因**：代码刻意「**不猜默认路径**」（好事），代价是"没配就没接"这件事**不会报错**（静默）。
- **预防**：收尾核查"某能力到底通没通"时，**先看配置有没有启用**，再看实现有没有写 —— 否则会把"没开开关"误记成"没做功能"。**反例**：本次差点按"重新实现"的方式去做 #5。

## 55. B 档构建**不加 `--out`** ⇒ 把 A 档产物**覆盖成 B 档内容**（2026-09-16，语料构建）

- **现象**：跑 `--tier B`（图省事没带 `--out`）之后，`--check --tier A` 报「产物与重算不一致 + 内容已变但版本未 bump」；核对发现 `frozen-private/knowledge/global.md` **多出了整节「五、项目文档索引（L3）」** = A 档产物被 B 档内容覆盖（98,966 B vs A 应有的 85,226 B）。
- **根因**：`--out` 的**默认值是 A 档目录**（`project/frozen-private`），`--tier` **不会**自动改输出目录 —— 文档里的正确写法是 `--tier B --out frozen-private-b`。
- **处置**：`--tier A`（默认 out）重建 → `--tier B --out frozen-private-b` 重建 → 两档分别 `--check`（A `9d3c27be68c98cba…` / B `38b3d16f91217536…`，均 exit 0）。
- **预防**：**A/B 两档的 `--out` 一律显式写全**；`--check` 也要带对应的 `--out`（不然校验的是默认目录，结论会串档）。**闸门之所以能报出来，正是因为它比的是「产物 vs 重算」，不是「文件在不在」**。

## 56. 「文档说没做」≠ 真没做 ⇒ 白跑一轮（幻影待办）（2026-09-16，[WB] `[L3]`）

- **现象**：待办 #2 写「`[L3]` 协议正文仍未写 ⇒ 升 v8」，依据是某设计文档里的一句「仍未写」；实际**逐字核对 `svn cat -r 570/-r 600` 后，该条款自 r570（协议 v6）就在正文里**，v6→v7 只补了 `[TOOL]`。
- **根因**：把「**这一轮的增量**只有 X」读成了「**整条**没写」；进度判断依赖**文档自述**而不是**产物**。
- **预防**：判「做没做」只认**产物与仓库**（`svn cat` / `grep` / 真机跑一遍）；文档里的自述一律当**线索**，不当结论。

## 57. 认证/权限类改动：**先分辨「声明层」还是「边界」**（2026-09-16，安全网关）

- **现象**：判定链写得再全，只要 **Agent 进程自己就能伸手**（自己实现 write/exec），「必须经过网关」就只是**纪律**，不是**边界** —— Agent 完全可以不走网关直接动文件。
- **根因**：把「我们代码里会检查」当成了「它做不到」。**判定者与被执行者同域 ⇒ 没有边界**。
- **预防**：任何安全改动先回答两问：① 谁能绕过它？② 绕过需要什么权限？—— 答不出就别称「边界」，老老实实叫「声明层」，并写明**硬边界仍未落地**。

## 58. macOS 系统级安装的三处「看起来没事」（2026-09-16，T3 launchd 服务）

- ① `mktemp -d` 建出来的是 **root 0700** ⇒ 再用 `sudo -u #<uid>` **降权**去写，写不进去（表现：对每个文件重试 10 次）。
- ② launchd 只按 `UserName` 换 uid，**gid 仍沿用 root** ⇒ 必须显式 `<key>GroupName</key>`，否则服务建的文件落在 `wheel`。
- ③ **macOS 新文件/套接字继承「父目录的组」**（不是进程的 egid）⇒ 想让某 uid 连上套接字，得把**父目录**的组设成它所属的组。
- 另：`File.Exists` 对**套接字文件**返回 `false` ⇒ 「存在就删」的陈旧清理**永远不生效**，重启直接 `EADDRINUSE`（症状：服务 `runs=2` 但 socket 不出现）。
- **预防**：系统级脚本的自检判据要写成「**真的能连上/能用**」，不要写成「文件在不在」。

## 59. 状态落点：**判不出基准位置就报错，绝不回退到 cwd**（2026-09-16，预授权账本）

- **现象**：`HOME` 指向不存在的位置时，`SpecialFolder.UserProfile` 返回**空串**，`Path.Combine("", ".agentruntime", …)` 变成**相对路径** ⇒ 预授权账本被写进了**仓库目录**（差点入库）。
- **预防**：① 判不出基准位置 ⇒ **抛错**（fail-closed）；② 测试别指望 `HOME=` 隔离（macOS 上 `GetFolderPath` 不认进程 `HOME`）⇒ 用**显式落点参数**；③ 跑完**核对外面有没有多出目录**。

## 60. 夹具会「吃掉」它要测的东西：多轮 + 回显前缀（2026-09-16，九例夹具）

- **现象**：mock provider 回显会给回复加 `[mock] 收到：` 前缀；单轮夹具靠**消息前置换行**让 `[TOOL]` 落在行首；而 `--chat` 的 `ReadLine()` **会吃掉那个换行** ⇒ 块头被挤到行中 ⇒ 解析不到工具（于是测的其实是「没有工具」的路径）。
- **预防**：夹具要断言「**被测量真的发生了**」（本处：事件流里真有 ToolResult）；多轮场景改用**同一 Runner 两轮**的集成测试，别硬凑 PTY 多轮。

## 62. 只验「文件在不在」的闸门 = 假绿（2026-09-16，skill-repo 全库汇总）

- **现象**：`build-skill-repo.py --only <少数技能>` 时 `write_repo_level` 只拿**本次处理的 metas** 写全库汇总 `_l1/_l2` ⇒ 30 技能被压成 3 行、188 问压成 1 问；而 `--check` **只验「文件在不在」** ⇒ **假绿**（静默丢 30 个技能的常驻 L1）。
- **根治**：① 汇总**恒从全库账本**（`*/.meta.json`）重算，与 `--only` 无关；② **写与校验共用同一函数**（构造上不可能不一致）；③ `check` 升级为「与全库账本**重算逐字节**比对」。
- **通用判据**：**校验必须与写入同源**；只要还问「文件在不在」而不问「内容对不对」，就会假绿。

## 63. 新加的「路径」字段漏进唯一解析处 ⇒ 按 cwd 猜（2026-09-16，skill.resident）

## 64. 长流程夹具三坑：只在新输出时判定 / 不复位世界 / 收尾提示吃 stdin（2026-09-16，真模型量表）

- **① 只在新输出时判定**：我的 PTY 夹具把「见审批面就点头」写在 `if 有新输出` 分支里 ⇒ **阻塞等输入的进程不再产生输出** ⇒ 夹具干等（实测卡 3 分钟无事件）。
  **修**：判定移到**每轮循环**都跑。
- **② 不复位世界**：上一轮的改动留在磁盘 ⇒ 模型读完发现「活已做完」而**合理地什么都不改**，被误判成「只读不改」。
  **修**：每轮跑前 `svn revert <目标>`，让「未完成」是事实。
- **③ 启动期的收尾确认先吃 stdin**：CLI 先问 `[收尾] 现在就收尾吗？[y/N]`（**`Console.ReadLine`，且是 `[y/N]` 不是 `(y/N)`**）⇒ 不答就卡死。
  **修**：夹具先答 `n`，再答审批。

## 65. 「看着有表 ≠ 表里有数」：正则漏字段 ⇒ 表空而闸门绿（2026-09-16，影子对照表）

## 66. 改名（口径/块名）必须扫到「量表」与「夹具」两处（2026-09-16，[SKILL]→[L3]）

- **量表**：`v6-skill-compliance.py` 扫的是字面量 `[SKILL]` ⇒ **块名一改，量表永远量到 0**（静默量不到，不报错）。⇒ 改名要连**度量工具**一起扫。
- **夹具**：协议预算负例原先写死 `new string('x', 80)` ⇒ 预算从 340 放宽到 400 后**不再越界**，负例失效（「正例绿」≠「夹具有效」）。⇒ 负例要**按预算算超出量**（`DeclaredMaxTokens * CharsPerToken + 8`）。
- **通用**：改一处**名字/预算**，要把「谁在按名字/按数值找它」全部列出来（量表、夹具、文档、历史记录）——**历史记录保持原样**，活表面全部跟上。

## 67. `LC_ALL=en_US.UTF-8` 全局 export 会波及同 shell 的 bash 脚本（2026-09-16，selftest）

- **现象**：`$var` **紧跟全角字符**（如 `$got（`）时，UTF-8 locale 下 **macOS bash 3.2 把全角字节吞进变量名** ⇒ `unbound variable`。本机 `LANG` 为空（C locale）所以一直没暴露 —— 按 `svn-workflow` 的习惯 `export LC_ALL=en_US.UTF-8` 才踩到。
- **预防**：脚本里所有「变量紧跟全角字符」一律写 `${var}`；**别全局 export LC_ALL**（只在单条 svn 命令前缀上带）。
- **小坑**：`pathlib.Path.write_text(newline=)` 在 **Python 3.9 不存在** ⇒ 用 `io.open(p, "w", encoding="utf-8", newline="\n")`。

## 68. 切轮用错了分隔符 ⇒ 多轮规模**静默少算**（2026-09-16，G6 双跑采集器）

- **现象**：`--verbose` 的逐轮诊断行**只有第 1 轮带 `[turn N]` 前缀**，第 2 轮起是裸行。采集器按「前缀切轮」⇒ 后续轮**全部塌进第 1 轮**（后写覆盖前写），表里「轮数」显示 1、prompt 只算第 1 轮。**没有任何报错**。
- **为什么危险**：它长成「表里有数」的样子（数字看着合理），却把多轮任务的规模**系统性少算**（实测 T3 少算 4 轮的 3 轮）。
- **修**：**用每轮的终结行切轮** —— `finish_reason` 每轮必有一行，见到就开新轮（`tools/double-run.py::parse_transcript`）。
- **通用**：凡是「从文本日志里切分记录」，别依赖**只出现在第一条**的装饰（前缀/横幅）；要依赖**每条都必有**的字段。

## 69. 审批计数：「项」不是「次」，且不许按累积缓冲区的文本出现次数计（2026-09-16，G6 采集器审批列；同日复核更正）

- **原判（已更正）**：G6 首跑 T2 报「审批 2 次」而事件流里只有 **1 个 `ToolResult`**，当时判为「终端重绘 / 回显把同一提示串**又出现一次** ⇒ 过计」。
- **复核（2026-09-16，同任务重跑 + 终端全文逐行核对）**：`pty.openpty()` 后直接读 master 是**字节流**，这条路径里**没有屏幕重绘**。真相是**单位错** —— 审批面**逐项**问人：一次 `exec` 的授权面 = `[1/2] proc.exec` + `[2/2] net.request` ⇒ **2 个提示 / 1 次工具运行**。终端全文里 `[审批] 执行？(y/N)` 出现 2 次、`[审批] 已点头（逐项…）` 2 次、面首行（`需要人工点头`）1 次 —— 与 1 个 `ToolResult` **完全自洽**。**「2」不是过计，是把「项」当成了「次」。**
- **真隐患（不是计数错，是会改走向）**：`buf.count(MARK) > approvals` 这个写法是「累积缓冲区里出现过几次」—— 一旦真的重读 / 重放缓冲区，同一提示会被**再答一次**，多写的那个 `y` 会落到**下一个**提示上（例如收尾确认 `[收尾] 现在就收尾吗`）当答复 ⇒ 静默改变会话走向。
- **修（2026-09-16）**：`src/AgentRuntime.Cli/e2e-shadow-stage1.py` ①计数改**游标消费**（`buf.find(MARK, cursor)`，游标只前进、已扫过的字节永不重扫）；②收尾报**两个单位**：`审批 N 项 / M 批`（批 = 一次工具运行的授权面）—— `tools/double-run.py` 的 `审批` 列取到的仍是**项数**（口径已写进工具）；③断言按**批**做 —— `批 ≤ ToolResult + ToolDenied`，另加独立对账 `项 == CLI「已点头」行数`，违反即打印 `[告警]`（`approval_warnings()`，正例不报 + 两条负例均报，夹具已验证）。
- **别照抄的写法**：`审批数 <= 工具结果数 + 被拒数` 若按**项**去比就**恒假**（实测健康跑：2 项 vs 1 个结果）⇒ 报警变成狼来了。**比大小之前先对齐单位。**
- **预防**：计数一律按**事件 / 按新增片段**计（流里的 `ToolResult` / `ToolDenied`、结构体），不按**文本出现**计；报数**必须带单位**（项 / 批 / 次 / 条），单位不同的两个数不许并列比较。
- **通用**：和 #65、#70 同族 —— **闸门 / 计数器报的数，必须能说清它是从哪个可复算的来源数出来的、单位是什么**。

## 70. 「命中率」不是同一把尺子：跨任务共享前缀 ≠ 会话内多轮（2026-09-16，G6 双跑）

- **现象**：[WB] 三题连跑**共享同一冻结前缀** ⇒ 命中 99.2~99.6%；[OC] 每题是**新会话** ⇒ 命中 5%（单轮）/ 51%（2~3 轮）。
- **风险**：直接把这两个数放一起比 ⇒ 得出「[OC] 缓存差得多」的**反向结论**，其实两者**分母范围不同**（跨任务 vs 会话内）。
- **预防**：报命中**必须同时报它的分母范围**（跨任务 / 会话内 / 单轮），并把「不是同一把尺子」写在数字旁边；需要严格对照时，令两侧的**冷/热状态**先对齐（同冷启动或同预热）。
- **通用**：属 §十·31「量法错家族」——**先问『这个比值的分子分母各是什么范围』，再比大小**。

## 71. [WB] 侧「路径基准」有两处暗礁：相对路径按 **CLI 目录**解析、常驻知识里的项目根是 **[OC] 副本路径**（2026-09-16，G7 有限切换 D1 实测）

## 72. 「空输出」不等于「没变化」：先看退出码与 stderr，再下结论（2026-09-17，G7 有限切换 D6 实测）

- **现象**（真机）：[WB] 首次跑 `svn status` **输出为空** —— 差点被读成「工作副本没改动」（真实情况是**那条命令自己失败了**；它随后修正写法才拿到真状态）。若按这个空结果继续，就会得出**反向结论**（「没改」→ 跳过核对 / 漏提交）。
- **为什么危险**：这是**静默失真**家族（§十·1 / #65 / #70）：命令失败**不一定会让你看见**，而「空」本身看起来很像一个合法结果。
- **预防**：① 任何命令的结论先看 **退出码 + stderr**，再看 stdout；② 关键判定**不用「看到空了就推定」**，而是让命令**自己证明**（例：`svn status` 空 ⇒ 再跑一次带 `--verbose`/区分「命令失败」与「无改动」的交叉检查；或像本工具族那样**断言有数**而非「在不在」，#62）；③ 取证 / 汇报类题面显式要求「**逐字回读**」（见清单 §三·10）。
- **未复现项（如实登记，不作结论）**：该跑还报「`--trust-server-cert-failures` 必须与 `--non-interactive` 同现，否则 `E205000`」；**在网关环境里两种写法都正常**（exit 0、输出相同）⇒ 登记为**待复现**，下次在 [WB] 的 exec 环境里两种写法对照。
- **通用**：**「我没看到」≠ 「没发生」**；凡是拿观测去支持结论的场合，观测本身要先自证（同族 #62/#65/#70）。
