# 知识库（四层树 · 单一入口）

> **只常驻 L1**；L2/L3/L4 由「扩散式下钻」按需取；同一 session 内同一条正文只拼一次，第二次只推指针。
> 节点标记（唯一格式）：`<!--kn: <id> [next=<id,id>] [src=<path>]-->`，单独一行，紧跟节点正文。
> id = `L<层>-<短名>-<三位>`；层号在 id 里，不另设按层标记。
> 树形关系：`L1 --扩散--> L2 --扩散--> L3 --扩散--> L4`，一对多是常态。

## L1 · 法则（常驻）

<!--kn: L1-iso-001 next=L2-iso-001-->
**产物隔离**：为运行服务的中间产物放系统缓存/临时区，不进用户可见区；自产目录必须进自身扫描排除名单。

<!--kn: L1-pfx-001 next=L2-pfx-001-->
**稳定前缀**：改头部一个字节 ⇒ 缓存整段作废；内容只追加；动态内容永不前置。

<!--kn: L1-evd-001 next=L2-evd-001-->
**证据优先**：说「完成」必须给出可复算的证据（命令 + 读数 + 复算方式），不接受自陈。

<!--kn: L1-err-001 next=L2-err-001-->
**坏数据报错**：不可重建的数据（地址表/账本）必须抛错；可重建的缓存才允许降级。

<!--kn: L1-gate-001 next=L2-gate-001-->
**闸门留牙**：用「应该红」的负例证明；分母 0 印 N/A 并计欠账，不许印 PASS；豁免默认不豁免。


<!--kn: L1-clm-001 next=L2-clm-001-->
**现象不冒称机制**：读数只能证明「与什么相关」；说出机制名必须指得出「哪条读数排除了其它解释」，否则只许写现象。


<!--kn: L1-side-001 next=L2-side-001-->
**探测会写**：判定「这条探测安不安全」不能看探测者的意图，只能看被探测系统会为它写什么。凡带写入副作用的状态（绑定、计数、审计），探测输入必须是必然失败且无副作用的那一类。


<!--kn: L1-byp-001 next=L2-byp-001-->
**人机闸门必有机器等价通道**：凡「只有人能过」的闸门（图形验证码、人工审批、手工点选），必须在同一处提供一条仅限隔离环境、可审计、默认关闭的机器通道；用完必须复验通道已关闭。缺这条通道的直接后果是端到端验收降级成「看源文件」。**且通道用过一次就必须固化成脚本**：手工跑通的路径若不能一键重现，下次只能重做，还得再冒一次「忘了复位」的险；固化的脚本本身就是复算方式，且必须做到「不碰生产实例、不留需人收尾的状态」。

<!--kn: L1-oop-001 next=L2-oop-001-->
**一处实现**：同一条规则只允许有一个实现处。多态替代分支 —— 新增一类能力等于新增一个类型，不改旧类型里的条件分支；判据是「新增时你动了哪里」。

<!--kn: L1-bak-001 next=L2-bak-001-->
**全量备份的成本由最大的那一件决定**：判「存下来要多大」不能看改了多少，要看占比前几名是什么；数据库、录音、压缩包、编译产物这类「每次重生成都是整份新内容」的东西，必须先挡在全量单位之外，否则每存一次就再付一整份。

## L3 · 处理单元（按需）

<!--kn: L3-iso-001 next=L4-iso-001-->
**做法**：产物目录与源目录显式分家；自产目录写进自身扫描排除名单；再加一条「产物不得出现在源清单」的闸门。

<!--kn: L3-pfx-001 next=L4-pfx-001-->
**做法**：把改头部的改动当版本事件对待；一次改够并成套重启；新增内容只追加，动态内容放尾部。

<!--kn: L3-evd-001 next=L4-evd-001-->
**做法**：证据三件套 —— ① 命令原文 ② 读数（计数/字节/sha）③ 复算方式（读者可独立重跑）。

<!--kn: L3-err-001 next=L4-err-001-->
**做法**：先把数据分账 —— 可重建（缓存/派生）允许降级并留痕；不可重建（地址表/账本）必须报错并说清「不在索引里」。降级写回时再加一条：**降级值不得覆盖更精确的既有读数** —— 保留原值并标「本次未复核」，或让该行显式变红计欠账；否则水位这类锚点会在探测失败时静默倒退。

<!--kn: L3-gate-001 next=L4-gate-001-->
**做法**：每个闸门配一个应红夹具；分母为 0 时印 N/A + 具名欠账；把闸门挂进流程（0 引用 = 没牙）。


<!--kn: L3-clm-001 next=L4-clm-001-->
**做法**：报告分两栏 —— 「观察到 X」（读数 + 复算方式）与「可能机制 Y（未证实）」。① 机制名后必须能写出排除了什么；写不出就删掉机制名。② 建议别人做代价高的动作（找管理员、重建库、回滚）前，先问「这条建议若错了，谁白跑」，并并列「若机制不成立，改走哪条路」。


<!--kn: L3-side-001 next=L4-side-001-->
**做法**：探针分两档 —— ①「端点活着吗」用必然被拒的输入（假密钥、空值、格式错），它产生零副作用；②「真数据能过吗」只在隔离数据根里种测试数据再打。事后校验三条：受影响表的行数、状态字段、审计行。


<!--kn: L3-byp-001 next=L4-byp-001-->
**做法**：四步 —— ① **先找既有通道**，别先造绕过（本例验证码调试头早已存在，读源码 30 秒就找到）；② 通道只在隔离环境开（Development + 本机回环），开之前记下它会把什么暴露出去；③ 一次跑完被测路径，每步留读数（登录 POST 的 302 目标、逐页状态码与页面标题）；④ **用完立刻复位并复验通道已关**（切回 Production 后重探调试头计数必须为 0、未登录仍 302）。缺第 ④ 步，一次验收就等于永久留了一个后门。⑤ **固化成脚本，且不动生产实例**：正确的隔离方式不是「把生产实例临时改成开发环境再改回来」，而是**另起一个临时实例**（单独端口 + 同一数据根 + 环境变量注入），脚本末尾用 trap 无条件杀掉它；脚本自带前置检查（产物在不在、生产是否 200、生产是否泄露调试头），并让退出码 0/1/2 分别表示全绿 / 有失败项 / 前置不满足。

<!--kn: L3-oop-001 next=L4-oop-001-->
**做法**：新增能力先问「是加类型还是改旧类型的分支」——改分支即退回重设计。状态与不变量交给构造函数（构造即合法），不给「先 new 再 set 到合法」的路径。同一条规则若出现第二处实现，抽基类或收敛到唯一声明处。

<!--kn: L3-bak-001 next=L4-bak-001-->
**做法**：五步 —— ① 先量占比前几名（`git ls-tree -r -l HEAD | sort -k4 -n | tail -8`），认出数据库 / 录音 / 压缩包 / 编译产物即先挡；② 排除表分五类写死（版本控制元数据 · 构建产物含可执行件 · 私密件 · 大二进制 · 本机垃圾）；③ 已经收错的**不删原文件**，用「重建单提交历史 + 两边 `reflog expire` + `gc --prune=now`」真正回收；④ 收完做一次**真恢复演练**（克隆到空目录，复算文件数 + 关键件逐一存在），不只看退出码；⑤ 判「远端可达 / 介质可用」只用会真出网或真读盘的读数，本地缓存不算证据。

## L4 · 重型知识（按需）

<!--kn: L4-iso-001-->
**证据**：影子跑把测试残留写进仓内自产目录，索引把 0 KB 残留当源收进去 ⇒ 语料闸门恒红。产物与源同目录是根因，不是闸门太严。

<!--kn: L4-pfx-001-->
**证据**：协议区改动 1 行即导致整段前缀缓存失效（实测代价约 4.6 倍）；因此格式面与协议区改动必须一次改够、一次重启带齐。

<!--kn: L4-evd-001-->
**证据**：「编译通过」「已修复」都不是证据；命令行全量编译 + 测试计数 + 产物 sha 才算。读数必须来自结构化源，不照人读文案抄。

<!--kn: L4-err-001-->
**证据**：地址表被静默跳过时，汇总照样印绿 ⇒ 假绿。修法不是改文案，而是让「读不到」变成一条有名字的红/警告。另一组（2026-10-21 收尾当场）：SVN 探针 3 秒超时触发降级，盖章把水位收敛点从已复核的 r136/r137 改写成 none，而同一次回执里 archive=136 仍在；自检判据只判「这一行已写」，于是事实层倒退而闸门全绿。对照：本轮把收敛点按回执读数写回后，回执与水位两处重新一致。

<!--kn: L4-gate-001-->
**证据**：某闸门分母为 0 却印 PASS，连续多轮无人发现；真红寄生于空转。改为 N/A + 具名警告后，空转立刻可见。另（2026-10-20 收尾当场）：`rules-changeOrder.md` 顶部写着「水位线（机器可判）· 指纹 `67770c02cc25`」，但全文件、`## 请求` 起至文末、去掉标题这三种切法的 sha256 前 12 位分别是 `39809053b660` / `059a60a75042` / `156528052bd7`，**没有一种复现得出旧值** ⇒ 判据写着「机器可判」，却没人能复算，等于没有判据。修法不是编一个新数，而是把口径当场写死在判据旁边：`sed -n '/^## 请求/,$p' rules-changeOrder.md | shasum -a 256 | cut -c1-12`，任何人可独立重跑。


<!--kn: L4-clm-001-->
**证据**：`E160006` 反复出现时，我做了一组对照 —— 失败文件的逐字节副本提交失败、同一副本追加一个空格后成功。这只能证明「结果与该文件字节相关」，我却写成「服务端 FSFS rep-cache 按内容哈希复用损坏 rep」，并据此建议管理员 `svnadmin verify` + 重建库。客户端无法区分服务端到底哪一层，这个机制名是**未证实**的。同为「把同时出现当成因为所以」的 **#332** 原样复发：那次把 license 提示当病因，这次把相关性当机制。代价是主人据此选了「等修复再导入」的方案，若机制不成立则空等。



<!--kn: L4-side-001-->
**证据**：授权服务器改造时，我用真密钥配假机器指纹探测 `/api/license/verify.xml`，返回 active 即把密钥绑到 `PROBE-DO-NOT-BIND`，`DeviceBindings` 当场多出一行。反证：改用必然失败的假密钥探测，返回 invalid 且零副作用。这组对照排除了「探测不会写」的假设 —— 有副作用的是端点语义，不是探测者的意图。



<!--kn: L4-byp-001-->
**证据**：2026-10-22 验收 5280 站点「登录后跳首页 + 会员中心 + 左侧菜单」。登录表单要图形验证码，答案只存 Session，生产环境无出口 ⇒ 一度只能读源码说「应该没问题」。查到 `Program.cs` 的 `/api/captcha` 本就有 `env.IsDevelopment() && debug` 分支把答案放进 `X-Captcha-Debug` 响应头；临时以 Development 重启后取到答案（实测 `5YPJ`），一次跑通：登录 POST 302 → `/`（首页），带会话逐页 200（仪表台 / 我的密钥 / 我的设备 / 绑定密钥 / 账户资料 / 改密码），侧栏 7 项。复位切回 Production 后，调试头计数复测为 **0**、未登录再探会员页仍 302。反证：若不查既有通道，只读源码，则「跳首页」这条结论永远不会被真实请求验证。**续（同日收尾）**：把它固化成 `/tmp/wb-login-check.sh`（7043 B）后实跑 16/16 全绿，且隔离方式比上一次更安全 —— 不重启生产实例，改用 `ASPNETCORE_ENVIRONMENT=Development` + `MAINWEB_DATA_DIR` 在**另一个端口**起临时实例，trap 收尾杀进程；跑后复验：5399 端口已释放、5280 仍是原 PID/Production、调试头计数 0。负例自证：未登录的生产首页不含「仪表台」但含「产品介绍」⇒ 说明关键字判据真能判红，不是空转。

<!--kn: L4-oop-001-->
**证据**：本轮把版本号 1.06 升 1.07 时，同一个数字散落在 `productVersion` 常量、注释、`CFBundleShortVersionString`、`CFBundleVersion` 四处，必须靠全局替换才同步；而窗口标题改为引用常量后自动跟随、无需再改。同一规则多处实现 = 每加一处就多一个必须记得改的地方，这是「一处实现」的可复算依据。

<!--kn: L4-bak-001-->
**证据（2026-10-22 · 建本机 git 兜底当场）**：为 SVN 离线兜底做首次全量快照，`git add -A` 直接把库撑到 1.8 GB。逐件查出膨胀源：行情数据库 1.9 GB、语音录音四段（每段 80~111 MB）、每次重新打包的 zip、能重新编译的 dll/exe。补排除表并以 `git checkout --orphan` 重建单提交历史、两侧 `reflog expire + gc --prune=now` 回收后，库降到 175 MB，纳管 5745 文件 / 内容 431.6 MB，`fsck` rc=0。**量化增量代价的对照实验**：10 MB 文本改 10 行 → 库涨 1 MB；10 MB 二进制改 2 字节 → 库涨 9 MB（整份重存）。**日常存档实测**：4 文件 / 55 行改动 → 仅增 112 KB。**恢复演练**：克隆到空目录，20522 文件全还原，八个关键件逐一命中，无版本控制元数据残留。**同轮第二组证据**：判服务器可达性时 `svn info` 0.017 秒返回（读的是工作副本缓存，看着像通了），而 `svn log -l 1` 两次超时、`nc -z` 对 80/443 均返回 1 —— 只有后两组关于"现在通不通"。
