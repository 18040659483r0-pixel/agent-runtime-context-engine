# Benchmark —— Agent Runtime 的「尺子」（独立于被测物）

> **铁则：尺子不能属于被测物。** 本目录**不是** Runtime 的组成部分，Runtime 也**永不**引用本目录。
> 否则会出现「Runtime 改了 → 顺手把 Benchmark 改了 → 数字变漂亮」，实验就失去意义。
>
> 规范版本：**V0.1**（2026-09-14 定稿，先于架构实现定义）
> 目标：无论 Runtime 演进到哪一层，都用**同一套尺子**给出 `Direct API` vs `Agent Runtime` 的可比数字。

## 0. 固定项（任何一次测量都必须锁定）

模型、Provider、参数、测试数据、测试流程、网络环境 —— **全部固定**。
任何一项变了，历史数据不可比，必须重新建立基线。

## 1. 五大类指标

| 类别 | 指标 | 最终回答的问题 |
|---|---|---|
| Token Efficiency | input / output / total tokens；重复 token；单任务总 token | 到底省了多少 Token |
| Cache Efficiency | cached tokens / uncached tokens / cache hit 率；缓存带来的成本与延迟变化 | 到底有多少输入被复用 |
| Execution Efficiency | 总延迟、TTFT、API 请求次数、吞吐、失败与重试次数 | 到底快了多少、稳不稳 |
| Runtime Overhead | Runtime 自身毫秒数（序列化 / context 处理 / 网络之外的开销） | 框架有没有拖后腿 |
| Task Equivalence | 两侧是否完成**完全相同**的任务：成功率 + 输出质量/验收结果 | 有没有「为省 Token 偷偷把活干少」 |

## 2. 第一阶段的 Test Unit

| 编号 | 形态 | 目的 |
|---|---|---|
| **T01** | 固定 Prompt → Model → Response | 建立最原始的 Token / Cost / Latency 基线 |
| **T02** | A / A / A / A（同一请求重复 4 次） | 观察上游到底有没有缓存、以及缓存真实带来的变化 |
| **T04** | 固定多轮脚本（自我介绍 → 依赖上下文的追问 → 再追问） | 测 **Session 维度**：是否真的完成任务（Task Equivalence）+ 每轮 prompt/cached 增长 |
| **T05** | 同一 T04 脚本 × 逐个开关模块（裸聊 / +Session / +Session+Memory …） | **模块消融（Ablation）**：量出每个框架模块的**边际价值**（token / 成本 / 延迟 / 能力） |
| **T06** | **冻结上下文阶梯**：三档规模（L0 空 / L1 1k / L2 10k token）× 三种形态（稳定追加 / 动态前置反例 / Runtime 路径）× 5 轮 | 直接对应 V2 的 **Frozen Context + Session Append Stream**：冻结多大、省多少、以及「前缀稳定性」到底值多少钱 |

> 注：早期曾有 `T03 前缀追加`，现已被 **T06 取代**（T06 = 真实语料 + 三档规模 + 变体隔离）。旧编号不再使用，避免历史数据口径混乱。

### 消融实验的两个硬前提（写在架构里，不靠自律）

1. **裸聊模式永远存在**：剥掉全部模块后，行为必须**等价于 V0**（一句话进、一句话出）。
2. **模块可单独移除**：去掉任何一个模块，其余模块的行为与去掉前**逐字节一致**（管线顺序、贡献内容都不受影响）。
   —— 已有测试守住（`消融_移除某模块后_其余模块贡献与移除前逐字一致`）。

### 实验纪律（每条都是踩过坑换来的）

1. **变体隔离**：每个变体的语料必须带唯一 salt，且 salt 必须放在**冻结前缀的最前面**。
   —— 放在尾部不够：前缀主体仍然相同，变体之间照样共享缓存命中（2026-09-14 第二轮才修干净）。
2. **冷启动自检**：每个变体的**第 1 轮必须 `cached = 0`**。若不为 0，说明有外部预热（校准调用/其它变体/重复 run），本次数据作废。
3. **原始记录优先**：报告只是视图；结论必须能从 `records.jsonl` 逐行复算。
4. **语料快照私有**：真实素材切出的冻结上下文含私有信息，只落 `local-corpus/`，**永不入公共仓库**。
5. **成本估算固定**：价格表写进 `benchmark.config.json` 并注明来源与日期。

## 2.5 已观测事实（实测，非设计目标）

**上游前缀缓存**

| 观测 | 数值 |
|---|---|
| 是否存在 | **存在**；DeepSeek 官方 V4 Flash 同时返回 `prompt_cache_hit_tokens` 与 `prompt_tokens_details.cached_tokens` |
| 粒度 | 命中量恒为 **64 的整数倍**（896=64×14、9856=64×154、256=64×4）→ 按 64-token 块对齐 |
| 短前缀 | 几十 token 的前缀**永远 0 命中**（曾误判为「上游不支持缓存」） |

**冻结上下文阶梯（`runs/20260914-183356-clean-ladder-r2/`，变体已隔离、第 1 轮均冷启动）**

| 档位 | 冻结规模 | 稳定形态：命中 / 单轮成本 / 节省 | 动态前置反例 |
|---|---|---|---|
| L0 | 0 字符（最小字节版） | 0 / $0.000015–34 / **0%** | — |
| L1 | 1771 字符 = **1000 token** | 896（89%）/ $0.000046–55 / **~67%** | 0 / $0.000149–192 / **0%** |
| L2 | 18760 字符 = **9974 token** | 9856（**98.4%**）/ $0.000299–308 / **~78.5%** | 0 / $0.001403–417 / **0%**（**4.7×**） |
| L1/L2 | 走 Runtime（rules+session） | 与手工直接调用**完全一致** | — |

> 结论（可写进论文实测栏）：**冻结上下文越大、前缀越稳，节省率越高（0% → 67% → 78.5%）；
> 而只要把「每轮都变」的内容放到最前面，收益立即归零。**
> 成本侧参照：cacheRead 单价 ≈ input 的 1/5（config: input 0.14 / cacheRead 0.028）。

## 3. 对照方式

```
Direct API   vs   Agent Runtime
```

同一组 Test Unit、同一模型、同一参数，跑两边，逐项对比。

## 4. 最终必须能回答的六个核心数字

| 指标 | 问题 |
|---|---|
| Total Tokens | 省了多少 Token |
| Cached Tokens | 有多少被复用 |
| Total Cost | 省了多少钱 |
| Latency | 快了多少 |
| Runtime Overhead | 框架有没有拖后腿 |
| Success Rate / Master Context | 有没有降低能力；Context 隔离省了多少 |

最终结论形态：`没有 Runtime → 有 Runtime：Token ↓x%、成本 ↓y%、速度 ↑z%、Master Context ↓w%`。

## 5. 实现约束（写入本目录时遵守）

- 独立可执行程序（`benchmark/AgentRuntime.Benchmark/`，第二阶段建），**只引用** Runtime，反向不成立。
- 每次运行落**原始记录**（JSON/CSV）：时间、模型、参数、每次请求的 usage 与耗时 —— 结论必须能从原始记录复算。
- 报告只写**实测**列；未测的写「尚无实测」，绝不把设计目标写成实测结果（与论文诚实性约定一致）。
- 测量 Runtime 侧时，`RuntimeTiming.RuntimeOverheadMs`（= 总耗时 − Provider 耗时）是唯一口径来源。
