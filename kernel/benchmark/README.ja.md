# Benchmark — Agent Runtime の「物差し」（被測定物から独立）

> [English](README.md) | [中文](README.zh-CN.md) | 日本語

> **鉄則：物差しは被測定物に属してはならない。** このディレクトリは Runtime の一部では**なく**、Runtime は
> ここを**決して**参照しません（「Runtime を変えた → Benchmark も変えた → 数字が良くなった」を防ぐため）。
> 仕様版：**V0.1**（2026-09-14 固定、アーキテクチャ実装前に定義）。目標：Runtime がどこまで進化しても、
> **同じ物差し**で `Direct API` と `Agent Runtime` の比較可能な数値を出すこと。

## `runs/` について

- `runs/` は**ローカルの証拠置き場**（`summary.md` / `records.jsonl` / ストリーム複製 / `-v` 診断）。
- **`runs/` 配下はコミットしません**（設計上）。本文中の `runs/<名前>/` はローカルポインタです。
- 58 個の run ディレクトリ（約 3.9 MB）は 2026-10-15 に本機から退避（主人令：実行記録は公開 SVN に入れない）。
  `runs/` 自体は版管理に残ります（空）。結論は `docs/` の要約・表から再計算できます。

## 0. 固定項目（測定ごとに固定する）

モデル・プロバイダ・パラメータ・テストデータ・手順・ネットワーク —— **すべて固定**。
一つでも変われば過去データは比較不能になり、ベースラインを取り直します。

## 1. 五つの指標ファミリ

| ファミリ | 指標 | 答える問い |
|---|---|---|
| Token Efficiency | input / output / total、重複トークン、タスク当たり合計 | 実際に何トークン節約したか |
| Cache Efficiency | cached / uncached、ヒット率、コストと遅延への影響 | 入力のうち何が再利用されたか |
| Execution Efficiency | 総遅延、TTFT、リクエスト数、スループット、失敗・再試行 | どれだけ速く、安定したか |
| Runtime Overhead | Runtime 自身のミリ秒（直列化・context 処理、ネットワークを除く） | フレームワークが足を引っ張っていないか |
| Task Equivalence | 両側が**同じ**タスクを完了したか（成功率＋出力品質） | トークン節約のために仕事を減らしていないか |

## 2. 第 1 段階のテストユニット

| ID | 形 | 目的 |
|---|---|---|
| **T01** | 固定プロンプト → モデル → 応答 | 素の Token / Cost / Latency ベースライン |
| **T02** | A / A / A / A（同一リクエスト 4 回） | 上流キャッシュの有無と実際の効果 |
| **T04** | 固定マルチターン台本 | **セッション次元**：タスク完了とターンごとの prompt/cached 増加 |
| **T05** | T04 × モジュールのオン／オフ | **モジュール・アブレーション**：各モジュールの限界価値 |
| **T06** | **凍結コンテキスト階段**：3 規模（L0 / L1 1k / L2 10k）× 3 形態 × 5 ターン | 凍結の大きさと、接頭辞安定性の価値 |
| **T07** | **凍結版の変更**：`v1→v1` / `v1→末尾追加` / `v1→先頭変更`、各 2 ターン | 「**どこを変えるかが、どれだけ変えるかより重要**」の定量化 |

> `T03`（接頭辞追加）は廃止。**T06 が代替**します（実コーパス・3 規模・変種隔離）。

### アブレーションの二つのハード前提（アーキテクチャに組み込み）

1. **ベアチャットは常に存在**：全モジュールを外すと V0 と等価。
2. **モジュールは個別に外せる**：どれを外しても他は**バイト同一**（テストで固定）。

### 実験規律（実測で学んだもの）

1. **変種隔離**：各変種のコーパスに固有 salt を**凍結接頭辞の先頭**に置く（末尾だけでは大半が共通でキャッシュを共有）。
2. **コールドスタート自己検査**：各変種の**第 1 ターンは `cached = 0`**。そうでなければ外部加温で無効。
3. **生記録が第一**：レポートはビュー。結論は `records.xml` から行単位で再計算できること。
4. **コーパスは私有**：実素材の切片は `local-corpus/` のみ、公開リポジトリには入れない。
5. **価格表は固定**：`benchmark.config.xml` に出典と日付つきで記載。

## 2.5 観測済みの事実（設計目標ではなく実測）

**上流接頭辞キャッシュ**

| 観測 | 値 |
|---|---|
| 有無 | **あり**（DeepSeek V4 Flash は `prompt_cache_hit_tokens` と `prompt_tokens_details.cached_tokens` を返す） |
| 粒度 | ヒット量は常に **64 の倍数**（896=64×14、9856=64×154）→ 64 トークンブロック整列 |
| 短い接頭辞 | 数十トークンでは**決してヒットしない** |

**凍結コンテキスト階段（変種隔離・第 1 ターンはコールド）**

| 段 | 凍結規模 | 安定形：ヒット / 1 ターン成本 / 節約 | 動的先頭の反例 |
|---|---|---|---|
| L0 | 0 文字 | 0 / $0.000015–34 / **0%** | — |
| L1 | 1771 文字 = **1,000 トークン** | 896（89%）/ $0.000046–55 / **~67%** | 0 / $0.000149–192 / **0%** |
| L2 | 18,760 文字 = **9,974 トークン** | 9856（**98.4%**）/ $0.000299–308 / **~78.5%** | 0 / $0.001403–417 / **0%**（**4.7×**） |
| L1/L2 | Runtime 経由 | 手動呼び出しと**完全一致** | — |

> **凍結が大きく安定するほど節約率は上がる（0% → 67% → 78.5%）。「毎ターン変わる」内容を先頭に置くと、
> 効果は即ゼロ。** コスト参考：cacheRead ≈ input の 1/5（0.14 対 0.028）。

**V4.1 セマンティックフォーカス A/B**（2026-09-15）：正答率 A 6/6 = B 6/6、cached 97.7% で同等、B は prompt +45。
⇒ アーキテクチャは成立、このフィクスチャでは効果未証明（天井）。長文脈（≥500k）でのコミュニティ再検証を公開
（`docs/EXPERIMENT-V4.1-FOCUS.md`）。

## 3. 比較の方法

```
Direct API   vs   Agent Runtime
```

同じテストユニット・同じモデル・同じパラメータで両側を走らせ、項目ごとに比較します。

## 4. 最終的に答えるべき六つの数字

| 指標 | 問い |
|---|---|
| Total tokens | 何トークン節約したか |
| Cached tokens | どれだけ再利用されたか |
| Total cost | いくら節約したか |
| Latency | どれだけ速くなったか |
| Runtime overhead | フレームワークが足を引っ張っていないか |
| Success rate / master context | 能力が落ちていないか、context 隔離でどれだけ節約したか |

結論の形：`Runtime なし → あり：tokens ↓x%、コスト ↓y%、速度 ↑z%、master context ↓w%`。

## 5. 実装上の制約

- 独立した実行プログラム（`benchmark/AgentRuntime.Benchmark/`）。Runtime を**参照**し、逆は禁止。
- 実行ごとに**生記録**（JSON/XML）を残す：時刻・モデル・パラメータ・各リクエストの usage と遅延。
- レポートは**実測**列のみ。未測定は「未測定」と書く。
- Runtime 側の測定は `RuntimeTiming.RuntimeOverheadMs`（総時間 − provider）が唯一の口径。

## コーパスロック（主人 2026-09-14 制定）

テストは**リポジトリ内 10K スライス**のみ使用可（`corpus/rules.md` + `corpus/knowledge.md` + `corpus/memory.md`、
17,990 文字 ≈ **9,569 トークン**）。私有の全量コーパス（`frozen-private/`、A 段 ≈24.5k）は**使用禁止**
（「凍結規模 → ヒット率 / コスト」が静かに比較不能になるため）。

四つのゲート（一つでも不合格なら停止）：

| # | ゲート | 挙動 |
|---|---|---|
| ① | `benchmark.config.xml` → `corpus.lock.allowedSources` | リポジトリ内の三相対パス**のみ**（絶対パス・`..` 禁止） |
| ② | 起動時 `CorpusLock.Verify`（`--plan` でも） | 違反 → **`exit 3`**（鍵取得・リクエスト送信の**前**） |
| ③ | `-- lock-corpus --check` | 指紋＋トークン上限。`--update` で再ロック |
| ④ | xUnit `CorpusLockTests`（4 件） | 許可リスト / 私有参照なし / 上限 / 指紋＋プライバシー |

標準手順：**コーパス変更 → `lock-corpus --update` → `dotnet test` → コミット**。
