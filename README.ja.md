# Agent Runtime / WhiteBox · v9.0（Alpha 0.1.5）

> English: [README.md](README.md) · 中文: [README.zh-CN.md](README.zh-CN.md) · リリースノート: [ALPHA-0.1.5-RELEASE.ja.md](ALPHA-0.1.5-RELEASE.ja.md)

**「透明・経済的・監査可能」を測定可能な数値として成立させた、単一セッションのエージェントランタイム。**

本書は現行実装の**包括的な設計・納品レポート**です。前版との差分ではありません。
システムが**今日なにであるか**、なにを保証するか、そして各保証が**どう測られるか**を記述します。

---

## 要旨

多くのエージェントランタイムは能力だけを最適化し、三つのことを測りません。モデルが実際に何を見たか、
いくらかかったか、なぜその動作をしたか。WhiteBox はこの三つを一級の工学的対象として扱います。

セッションは**追記専用のイベントストリーム一本**です。モデルに渡すバイト列は**安定プレフィックス**
（プロトコル → ルール → 知識 L1 → 意思決定 L1 → メモリ索引）とそのストリームから組み立てられ、
プレフィックスはターン間で**バイト単位で同一**なので、重い処理はプロバイダのプレフィックスキャッシュに任せられます。
知識と意思決定は**同型の四層ツリー**で、本文は id で取得し、同一セッション内では一度しか組み立てません。
すべての行為は**タグ付きイベント**、すべての判断は**反例を持つゲート**、すべての収尾は**再計算可能なレシート**です。

参考ワークロードでの実測：プロトコル領域 **25 行 / 5,234 token**、知識ツリー **10 / 25 / 46 / 445** ノード、
意思決定ツリー **4 / 8 / 12 / 16**、内部テスト **1349 / 1349**、実長セッションのプレフィックスキャッシュ命中
**99.1 %**、423 ターンの台帳圧縮 **45,888 → 16,599 文字（−64 %）**、収尾 **約 35 秒 / 5 ラウンド**。

## 0. 最初の約束は、果たされました

プロジェクトの出発点は一文でした：*単一セッションで、可能な限り透明・経済的・監査可能に。*
本版はその一文を締めます。

| 約束 | 仕組み | 実測（2026-10-30） |
|---|---|---|
| **単一セッション** | 1 プロセスが 1 ストリームを所有。`/reset` が終了の唯一の手段。`start` が前回の末態から次を開く | `--stream` は常に 1 ファイル。再開・再生は**位置**の意味論で、マージではない |
| **透明** | 追記専用イベント。`Tag` が同一性。プロンプトは計算されたオブジェクト | 12 モジュール、モジュール別の寄与バイトが画面に出る（`(Cached) / (Active) / (Runtime)`） |
| **経済的** | 常駐は L1 のみ。L2–L4 は id 取得。1 ターン 1 回組み立て。安定プレフィックスは書き換えない | キャッシュ命中 **99.1 %**（296,225 / 293,632）、プロトコル **5,234 token**（予算 5,600） |
| **監査可能** | タグ・台帳・反例付きゲート・収尾レシート・意思決定レポート | **18** の block/report 検査、**242** 件の落とし穴配置宣言、レシート指紋は再計算可能 |

以下はすべて、この表の背後にある仕組みです。

## 1. なぜ通常のエージェントランタイムはこの四つに落ちるのか

1. **透明性が最初に死ぬ。** プロンプトは場当たり的に組み立てられ、どのバイトがどこ由来か、予告と実送が同じかも言えない。
2. **コストが見えなくなる。** 履歴が伸びるたびに全体を再送し、請求は二次関数的に増え、キャッシュ命中率は測られない。
3. **監査が考古学になる。** 実行時の判断（取得・収尾・知識昇格）はログ行しか残さない。
4. **セッションが互いに汚染する。** 「全部持ち越す」で連続性を作るので、各節が前より遅く不確実になる。

WhiteBox はこの四つに、規律ではなく仕組みで答えます。

## 2. 設計不変条件

| # | 不変条件 | 担保 |
|---|---|---|
| I1 | 版イベントを宣言しない限り、安定プレフィックスはターン間でバイト同一 | プレフィックス指紋 + 版台帳 |
| I2 | 履歴は追記のみ。書き換えも折り畳みもしない | 折り畳み経路が存在しない。境界ではセッションを換える |
| I3 | 1 ターン = 1 回の組み立て。見せたものが送られたもの | `Assert.Same(preview.Request, client.LastRequest)` |
| I4 | 同一ノード本文はセッション内で一度だけ。以後はポインタ | id 取得 + セッション内重複排除 |
| I5 | すべての判断に、赤くできる反例がある | ゲート（実行時 18 検査 + 単体 1,349 件） |
| I6 | 黙って飛ばさない。不正入力は位置付きで fail-closed | 行番号付き `InvalidDataException` |

## 3. アーキテクチャ

### 3.1 領域とバイト会計

プロンプトは名前付き領域の積み重ねで、それぞれに予算と寿命があります。

| 領域 | 内容 | 寿命 |
|---|---|---|
| **R1-P** | プロトコル領域（v102）— カーネル定数・rank 0 | 版イベントまで安定 |
| **R1** | ルール · 知識 L1 · 意思決定 L1 · メモリ索引 | 安定プレフィックス（変更時のみ再派生） |
| **R2** | 追記専用のセッションイベントストリーム | 追記のみ、書き換えなし |
| **R3** | フォーカス — いま何のタスクか | ターン単位 |
| **R4 / R5** | ホワイトボード / 下書き — セッションを跨ぐ作業面 | 収尾でスナップショット、黙って捨てない |

画面は**直前のリクエストにおける各モジュールの実寄与**と**次ターンの推定**を同時に出し、
推定は推定として明示されます。推定が事実の顔をすることはありません。

### 3.2 イベントストリームが唯一の事実源

ユーザ発話・モデル出力・ツール呼び出しと結果・ヒント・判断・中断・収尾は、すべて単調増加の連番とタグ
（`E001`、`E002`…）を持つイベントです。位置はストリームから導かれ、外に権威はありません。結果：

- クラッシュ解析は末尾を読むだけ（最後の三件が「何をしていたか」に答える）。
- セッション間の引き継ぎは位置の意味論（`S<k>/E###` アンカー）。文章の写しではない。
- どの数値も、後から誰でもファイルから再計算できる。

### 3.3 二つの同型ツリー

知識（何を知っているか）と意思決定（なぜそう選ぶか）は同じ形です。

```
L1 法則 → L2 問いの形 → L3 処理単位 → L4 逐語証拠
```

- 各ノードは**親をちょうど一つ**。深さはちょうど四。上層は必ず**まとめる**役割を果たす
  （L1 が L2 を一つしか覆わないなら抽象化の失敗で、連鎖ゲートが赤にします）。
- L1 は常駐、L2–L4 は id 取得。ノード本文がコンテキストに入るのはセッション内で一度。
- L4 は証拠層：逐語・追記のみ、各項目に `src=` アンカー。
- ノード id は正規形（`L<層>-<短名[a-z0-9]{2,16}>-<三桁連番>`）。規格外のマーカーは**解析エラー**で、飛ばしません。

現在の参考コーパス：知識 **10 / 25 / 46 / 445** ノード（516 辺）、意思決定 **4 / 8 / 12 / 16**。

### 3.4 十二のモジュール、一度の組み立て

| モジュール | 役割 | 目安バイト |
|---|---|---|
| protocol | カーネル契約（R1-P） | 約 20.9 k 文字 |
| rules | 工学ルール | 約 31 k 文字 |
| knowledge | L1 法則 | 約 5.6 k 文字 |
| decision | L1 取向 | 約 1.5 k 文字 |
| memory-index | ページ索引（必要時取得） | 常駐 0 |
| append-stream | セッション履歴 | 増加 |
| task-ledger | 1 ターン 1 行：意図 / 結果 / 終局 / 未決 | 約 0.3 k 文字 |
| tool | ツール面（プロトコル領域） | 常駐 0 |
| note | ターン内メモ | 未使用時 0 |
| current-tail | ホワイトボード（R4） | 小 |
| dynamic-draft | 下書き（R5） | 小 |
| focus | フォーカス（R3） | 小 |

画面は**そのターンに実際に寄与したバイト数**でラベルを付けます：`(Cached)` はリクエストに組み込まれた、
`(Active)` は活版から必要時取得、`(Runtime)` は搭載のみで寄与なし。
ラベルはリクエストを生成した**同じ組み立てトレース**から来ます（二度目の計算ではありません）。

### 3.5 セッションのライフサイクル

```
収尾（収束 + 水位 + 末態スナップショット）
   → reset（旧ストリームをアーカイブし、セッションを閉じる）
      → start（新しい空ストリーム。ボードと下書きはスナップショットから引き継ぐ）
```

- 収尾は固定パイプライン：`--check` → `--apply` → `--promote` → `--close` → `--check`。
  `--l4-sync` が新しい証拠を L4 へ移し、`--kn-plan/--kn-link` が正しい親に接続します。
- パイプラインは**機械的**：本文の移動、版の繰り上げ、派生の再生成。意味判断はモデルの仕事で、実行時は推測しません。
- 閉じたセッションは次を妨げません。起動時に `closed` を見たら新しいストリームを開き、引き継いだ内容を逐一表示します。

## 4. 仕組み

### 4.1 経済性

- **常駐は決定であって偶然ではない。** 各ツリーの L1 だけがプレフィックスに入り、他はアドレス可能。
- **1 ターン 1 回の組み立て。** プレビューのオブジェクトがそのまま送られる（参照等価で固定）。
- **安定プレフィックス。** 時刻・カウンタ・環境値を成長部より前に置かない。成長は常に末尾。
  この一行がキャッシュ命中を理論上限近くに保ちます。
- **窓は境界であり、圧縮ではない。** 1,000,000 token の 80 % で収尾して次へ。黙って品質を落としません。

### 4.2 透明性

- **すべてのバイトに持ち主がいる。** 領域スタック、モジュール別寄与、キャッシュ命中率、コンテキスト合計は
  同一の組み立てトレースから読みます。
- **混ぜてはいけない二つの数**：「このタスクが書いた量」（累積）と「いまのコンテキスト」（直前に実送したプロンプト）。
- **数値は構造化された源から**（イベント種別・台帳）。人が読む文章を削って取ることはしません。

### 4.3 監査可能性

- **歯のあるゲート。** 実行時 18 検査：プレフィックス/版、コーパスロック、台帳照合、アーカイブ一致、
  未登録ファイル、到達性前提、削除登録、知識ツリー連鎖（単親 / 層序 / 到達 / 深さ）、L4 出典アンカー、
  意思決定ツリー連鎖、意思決定ライブラリ昇格、前回リリースからの成長、落とし穴配置の完全性。
  block 級の各ゲートは**必ず赤くなる反例**で証明されます。
- **配置の宣言。** 新しい落とし穴は `gate / resident / human / todo` のいずれかで宣言し、ポインタは宙に浮かせない
  （現在 242 件。`todo` は明示的な基準で上限を切り、負債が静かに積み上がらないようにしています）。
- **レシート。** 収尾は指紋付きのレシートを残します。作業区が変わってレシートが変わっていなければ、それ自体が赤です。

### 4.4 停止点のある自律

- 意思決定ライブラリは**取向**（L1）から**逐語の先例**（L4）までを符号化します。判断が必要なときの既定は
  **止まって尋ねる**こと：1〜3 の選択肢、各々の帰結、そして従った L1 を引用した推奨を添えます。
- 連続作業は**明示的な停止点**で区切られます。停止点が与えられれば、中間判断をライブラリで埋めて
  ちょうどそこで止まります。与えられなければ、まず停止点を尋ねます。
- だから「自律」は「無責任」ではありません。自動の判断はすべてライブラリの項目に遡れます。

### 4.5 一つの画面、三つの言語

- v9.0 で端末画面は一つ（TUI2）だけになり、旧画面は**完全に退役**しました（フラグの裏に隠れてはいません）。
- インターフェースは**強型の文言テーブル**：89 キー × 英語 / 日本語 / 中国語、**既定は英語**、実行時に切替可能。
  キーの綴り間違いや欠落はコンパイルエラー。さらに「英語時に漢字を出さない」ことを断言するゲートがあります。
- 診断能力は失われていません。未処理例外は従来どおり記録されます（ストリーム末尾 + ポインタ + マネージドスタック）。

## 6. 意図的にやらないこと

- **実行時に意味を推測しない。** 構造が解析できなければ位置を報告して止まります。「もっともらしい読み」を捏造しません。
- **静かな降格をしない。** 資源欠如は `source_missing`。取得できない数値は「取れない」と言い、0 を印刷しません。
- **無界のコンテキストを作らない。** 履歴の折り畳みも要約もしません。セッション境界は明示的です。
- **書き込みを隠さない。** 耐久状態の変更はすべて名前付きで grep 可能な入口を通り、収尾レシートがそれを覆います。
- **マルチユーザ / 並列セッションを主張しない。** 一度に一つは設計判断であり、見落としではありません。並列は別の研究線です。

## 7. 再現

```bash
cd kernel
dotnet build AgentRuntime.slnx -c Release          # エラー 0
dotnet test tests/AgentRuntime.Tests -c Release    # 公開スライス 1347/1349
dotnet src/AgentRuntime.Cli/bin/Release/net10.0/AgentRuntime.Cli.dll --protocol-show
dotnet src/AgentRuntime.Cli/bin/Release/net10.0/AgentRuntime.Cli.dll --kn-check whitebox/workspace
```

`--protocol-show` は版・規模・予算を、`--kn-check` は層ごとのノード数・辺数・派生層の逐バイト一致を出力します。
同じ入力なら同じ数値です。

## 8. ロードマップ

1. **スループットと遅延** — まず測り、その後に最適化。pre-release のままである唯一の理由です。
2. **意味論的カバレッジの回復** — 旧画面の退役で失った三本（意思決定レポートの紐付け / 自己報告表示 / 継続上限）を新画面で再建。
3. **長期的研究** — 同一タスクの複数セッションを、台帳を監査記録として観察。
